# AudiPick 智能合同审阅迁移差异记录

基线：`modules/AudiPick/`（Electron 31 + 原生 JS，约 6,663 行，无 React、无打包器）。
目标：`src-tauri/src/audipick.rs`（570 行）+ `storage.rs` 的 AudiPick 表 + `App.tsx` 内的 `AudiPickPage`。

**这也是 2026-08-05 之前没有任何迁移文档的工具**，且新旧技术栈完全不同、后端最薄、前端最重。

## 规则层：逐文件核对，内容一致

`modules/AudiPick/rules/**` 与 `tauri-app/assets/audipick/rules/**` 共 19 个文件（13 个提示词、
收入底稿问题矩阵、注册表、字段集等）逐个比对**内容完全相同**，且新版启动时确实加载。
"提取模板漂移"这一类担心可以排除——**变的是这些内容如何被使用**。

## 2026-08-05 已修复

- **长合同不分段**：旧版超一万字自动切成 8000 字一段、段间续接页码标记、3 段并发；
  新版整篇一次性发出且未设输出上限。后果是超长合同要么报错，要么**模型只读了前半段、后半段契约条款静默漏提**，
  而界面照样显示"提取成功，返回 N 条"。已按旧版切分（含页码标记续接），并补单元测试锁定"不丢内容""每段带页码标记"。
- **收入底稿两阶段问答缺失**：旧版先对资料包每份文件抽取**不含会计结论的客观事实**（付款条件、交付验收、
  退货回购、返利折扣、是否引用 SOW）形成共享事实表，再把 43 道题分 5 批作答并用事实表回填
  （如按付款期限天数自动判定"是否存在重大融资成分"，资料包缺 SOW 时降级为需复核）。
  新版曾与其余 12 个模板走同一条路：整份文本 + 原始提示词一次性问 43 题，几乎必然漏答或被截断。已重建两阶段流程。
- **收入底稿导出丢失填列映射**：旧版导出 25 个中文列，含**工作表名称、底稿行号、回答/理由/摘录三个目标单元格**——
  这份映射正是该模板的核心价值；新版按字母序输出英文原始键名，清单从"可执行的填列指令"退化为"需人工重新定位的原始数据"。
  映射数据本就在规则文件里且已加载，只是导出时未调用。已接上（导出支持调用方指定列顺序）。
- **"待补资料"永远显示占位文字**：规则模块输出 `text` / `questionNos` / `blocking`，界面却先读 `title`，
  每条都落到兜底文案"需要补充支持资料"。数字是对的，内容全是废话。已修正并显示涉及题号与是否阻塞。
- **"自动不适用"过滤未生效**：合同无回购条款时其两道子问题应被隐藏，规则已打标记，展示与导出都不读。已生效。
- **删除项目/文件无二次确认**：点击即删，连带该项目全部 PDF、提取结果与复核标记，无撤销。
  （全应用此前仅 Roll Forward 有三处确认。）已补，并写明会一并删除什么。
- **文档类型自动识别整体缺失**：模板下拉永远停在"借款·限制性契约"，选错不会有任何提示。
  旧版 `classify.js` 依赖 Electron 全局与自有 HTTP，无法直接移植；改为复用现有 `audipick.classify` 接口、
  在前端按当前模板清单动态拼提示词。**采用"给建议 + 人工确认"而非静默切换**，模型返回不存在的模板 id 时退回当前模板。
- **证据页跳转不看来源文件**：资料包场景下会在当前打开的 PDF 上跳页，看到的是无关内容，
  用户会以为模型编造了证据。现按结果的来源文件字段匹配到对应 PDF 再跳（按文件名长度倒序匹配，
  避免"主合同.pdf"抢走"主合同补充协议.pdf"的引用）。
- **无提取缓存**：同一合同、同一模板、同一字段组合重复提取会再烧一遍 token，且因模型随机性结果还不一样。
  已按"合同 + 模板 + 字段组合 + 上下文内容指纹"缓存，关联资料一变即失效。
- **调用失败不重试**：批量跑 30 份，网络抖动就有几份失败需手动找出重跑。已加 3 次重试并显示剩余次数。
- **批量提取失败清单不显眼**：worker 逐份回报成功/失败与原因，界面只显示进度条。已单独列出。
- **请求缺少关键参数**：旧版每次调用都下发 `thinking:{type:disabled}` 与（DeepSeek 下）`response_format`，
  迁移时两个都漏了，推理型模型会先跑思维链再吐 JSON。与 FA List 同一处病根，已一并修复。
- **错误信息不可诊断**：与 `fa.rs` 相同的"先解析 JSON 再判状态"问题，已改为先取文本、再判状态、最后解析。

## 仍未清零

- **OCR 从三条路收窄到两条，离线那条没了**：旧版可选浏览器本地 Tesseract（完全离线）、AI 视觉、
  或任意第三方接口（含百度两个预设与本机代理）；新版只剩统一 AI 视觉与百度高精度，
  **两条都必须联网且都要把合同页面图片发到外部服务**。受限网络或数据出境敏感的项目上，扫描件无法处理。
- **OCR 无法单独配置视觉模型**，只能复用工具箱全局 LLM。
- **模板库页面缺失**：旧版有分类、搜索、字段清单、真实示例；新版只有一个下拉框加一行简介。
- **自定义模板只能新建**，不能以内置模板为基础复制，也不能编辑或删除。
- **同一合同的多套提取版本无法保留与对比**（数据结构支持，界面未做）。
- **导出只剩"当前文件 + 当前模板"**，旧版可导整项目并按模板拆 Sheet。
- **底稿结果只读**，人工修正无法回存。
- **处理工作日志抽屉与日志导出缺失**。
- **通用模板导出仍用英文键名、按字母序**，且金额为文本（旧版用中文标签、识别金额列并套千分位）。
- **批量提取有隐藏前置条件**：读取 PDF 后必须点过"保存文字"，否则整批失败，界面无任何说明。
- **OCR 未配置时扫描件静默跳过 OCR**，AI 拿到近乎空白的文本，结果不可信但看不出来。
- **旧数据迁移预计丢四样**（未实机验证）：导入的 PDF 描述信息写空导致文件列表读取报错、
  历史提取结果因字段组合标识算法不同被全部过滤（数据在库但看不见）、补充资料从属关系丢失、
  合同文字不在备份内需重读（扫描件要重跑 OCR）。

## 新版明确更好

完全离线可用（旧版界面样式与浏览器 OCR 依赖境外 CDN）、密钥进 Windows 凭据管理器
（旧版明文存 localStorage）、备份改为 zip + 逐 PDF 哈希校验 + 导入失败整体回滚
（旧版把所有 PDF 转 base64 塞进单个 JSON，几十份即撑爆内存且零校验）、
批量任务跑在独立进程可真正暂停/取消/崩溃隔离。
