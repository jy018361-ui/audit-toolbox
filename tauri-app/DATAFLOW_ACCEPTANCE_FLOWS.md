# 数据流（DataFlow）首版验收流程规格

> 来源：依据《DATAFLOW_DESIGN.md》v0.3（2026-10-27）编制，术语以设计文档为准。
> 编制日期：2026-10-27
> 测试数据均为合成或脱敏，不入库业务数据。
> 承诺状态说明：**增量重跑**（即设计文档第 7 节「缓存复用重跑」：未变化的输入与上游结果直接复用，只重跑改动部分；设计文档已明确其不是把新到数据追加到旧结果的"增量计算"）、**自动保存**、**文件夹续期对比**、**流程配置摘要导出** 四项，经 2026-10-27 复核为**用户已确认的首版承诺**，本文一律按首版必验项编写，不标记"待确认"。
> 本文只描述验收要求与测试数据构造方案，不含任何实现方式。行数一律以"行数量级"表述，不写死具体数字；键分布占比为构造目标值，验收记录须登记实际生成值。

## 1. 通用验收约定（三条流程均适用）

### 1.1 每条流程都要通过的五个环节（对应设计文档第 13 节）

1. **搭得出来**：仅用首版 20 个节点在画布上搭出流程；
2. **预览跑通**：预览运行全程无任务级错误，界面常驻「预览模式·样本数据」横幅，输出节点不落盘、只在结果区展示；
3. **全量正确**：全量运行结果与独立基准（Excel 手工复算 / 工具箱现有工具 / 构造侧已知答案）一致，逐项记录预期与差异；
4. **换数重跑**：另备一套同结构、不同期间的数据，经**参数确认页**修改输入路径与期间参数后重跑成功；
5. **跨机复用**：流程文件复制到另一台电脑打开，参数确认页重新选择文件（流程内的路径文字不等于访问授权），跑通且结果口径一致。

### 1.2 通用检查点（各流程清单不再重复）

| 检查点 | 设计文档依据 |
| --- | --- |
| 预览运行不写输出文件；预览与全量缓存隔离，不得串用 | 第 7 节 |
| 全量运行完成显示摘要（总耗时、各节点行数、警告数）；带跳过记录的成功运行标为"有警告"（黄色） | 第 7 节 |
| 输出覆盖保护：目标文件已存在时默认报错；可配置自动加时间戳或直接覆盖 | 第 7 节 |
| 正式输出完整性：先写临时文件、成功后按覆盖策略提交；失败或取消不留"貌似成功"的文件；多个输出部分成功时逐项列出，标记"部分输出成功"，不显示整体成功 | 第 7 节 |
| 进度与取消：支持取消；全局排序等阶段显示阶段状态，不伪造精确百分比；已完成且仍有效的节点结果保留，未完成缓存不发布 | 第 7 节 |
| 行级异常策略：转换失败默认停止；配置为"跳过整行并记录"时，异常清单含节点、字段、原值、原因、来源与数量，并在运行摘要披露；结构性/任务级错误必须停止，不能套用跳过策略 | 第 7 节 |
| 参数确认页：打开流程先列全部参数与当前值；输出文件名可引用参数（如期间） | 第 6 节 |
| 字段引用校验在打开、保存、运行三个时机执行，集中提示"哪个节点引用了哪个字段、现在输入里没有" | 第 6 节 |
| 流程文件带版本号；旧版流程自动升级并明确提示；无法兼容时明确报错 | 第 6 节 |
| 自动保存：编辑过程自动存草稿，异常关闭后再次打开提示恢复（首版承诺） | 第 6 节 |
| 文件夹续期对比：文件夹批量重跑时报告"本次读到几个文件、比上次多了哪些、少了哪些"（首版承诺） | 第 6 节 |
| 流程配置摘要导出：区分预览与全量，含流程名、运行标识与状态、参数、业务日期、各节点关键配置与进出行数耗时、来源文件清单、跳过记录数量、输出清单，可直接粘入底稿（首版承诺） | 第 11 节 |
| 结果区的查看筛选/排序/搜索只改变查看方式，不改变节点输出与下游数据；历史失效结果有标记，不得作为本次正式结果导出 | 第 7、8 节 |
| 类型锁定、前导零编号保留、"超过 12 位"不统一转文本、金额精度与显示分离（不统一截两位） | 第 9 节 |

### 1.3 增量重跑专项（首版承诺，以流程一为载体，覆盖设计文档 13.2 要求的全部情形）

| 情形 | 操作 | 预期 |
| --- | --- | --- |
| 已有缓存 | 只改下游一条公式（如借方金额公式） | 不重读 12 个输入文件，复用输入与上游缓存，仅改动节点及下游重跑 |
| 已清理缓存 | 在设置页清理节点缓存后再跑 | 允许重算并在运行摘要解释原因 |
| 输入变化 | 修改任一序时账文件内容 | 相关节点标"需重跑"，新旧结果不混用 |
| 手工小表变化 | 修改科目映射表一行内容 | 关联及下游失效重跑 |
| 参数变化 | 只改"金额门槛"数字参数 | 仅筛选及下游重跑 |
| 跨日运行 | 次日重跑（流程用到"今天"类函数时） | 缓存失效判断包含业务日期，运行摘要记录当日业务日期 |

验收观察口径：节点"复用 / 需重跑"状态标记、运行摘要披露内容、重跑耗时与首跑对比；旧结果保留查看但明确标记历史运行与失效状态。

### 1.4 测试数据构造总原则

- 全部合成或脱敏，不使用入库业务数据；构造数据的同时产出**构造侧已知答案**（行数、键分组计数、合计数、每类问题数据的落位预期），供独立对拍；
- 每一条埋入的问题数据都要在验收记录中登记：埋在哪个文件哪一段、期望落到哪一路输出或哪条检查规则、实际结果如何；
- 问题数据尽量埋在**预览采样取不到的位置（文件后半段）**，用于验证"预览通过不代表全量结果正确"。

## 2. 验收流程一：批量清洗合并（全年序时账清洗汇总）

### 2.1 流程目的与业务场景

审计人员拿到被审计单位全年逐月的序时账（凭证库），各月文件格式不一（表格与文本混放、编码分隔符不齐）。需要把 12 个月合并成一张全年明细大表、挂上科目映射，再按客商汇总发生额、筛出大额往来，形成底稿的明细表与汇总表。

### 2.2 输入数据清单

| 数据 | 形态与规模 | 字段清单 | 行数量级 |
| --- | --- | --- | --- |
| 序时账·表格类文件夹 | 8 个月度文件：7 个 xlsx（其中 1 个含多 Sheet：数据 Sheet＋"试算平衡" Sheet 需排除）、1 个后缀 .xls 实为 GBK 制表符分隔文本的**伪 xls**；Sheet 名不统一（"序时账""202601"等） | 凭证日期、凭证号、摘要、科目编码、科目名称、借贷方向、金额、客商名称、对方科目编码 | 每文件万行级，合计十万行级 |
| 序时账·文本类文件夹 | 4 个月度 csv：编码混排（GBK、UTF-8 带 BOM、UTF-8 无 BOM），分隔符混排（逗号为主，混入 1 个分号或 Tab） | 同上，但**没有**"对方科目编码"列（用于纵向合并差异报告） | 每文件万行级 |
| 科目映射表 | 手工输入节点粘贴的小表 | 科目编码、科目大类（资产/负债/权益/成本/损益）、报表项目 | 百行级（覆盖明细用到的全部科目，另含若干未使用科目、故意缺失 2 个明细中用到的科目编码） |
| 第二套数据（换数重跑用） | 同结构的另一期间文件夹＋新映射表 | 同上 | 同量级减档 |

**故意埋入的问题数据（逐项验收）**：

| 问题类型 | 埋法 | 期望行为 |
| --- | --- | --- |
| 金额带千分位 | 若干行金额为文本"1,234,567.89"（xlsx 文本单元格；分号/Tab 分隔的 csv 中亦可埋） | 清洗节点文本替换去掉逗号后，公式转十进制小数成功 |
| 全角数字与全角负号括号 | 个别金额为"１２３４．５６"、负数写作"（1,000.00）"（全角括号） | 全角转半角后正确转数；括号负数按预设动作或公式处理为负值 |
| 客商名称脏数据 | 全角括号"（母公司）"、首尾空格、中间不可见字符、全半角字母混写（"ＡＢＣ公司"与"ABC公司"并存） | 清洗后归一为同一写法，同一客商进同一汇总组 |
| 空值与空文本 | 摘要空值、客商为空文本、金额空值、整行空记录若干 | 空客商不并入其他组、单独成组呈现；整行空记录被"删除整行空记录"动作删除并在统计可见 |
| 重复凭证号 | 同月内少量重复凭证号 | 不做拦截（唯一性校验属检查节点职责，本流程仅核对行数时知悉即可） |
| 后半段类型异常 | 文件后半段（预览采样取不到处）埋同一张凭证的借贷两行，金额均为文本"待定"，两行金额相等 | 输入/公式节点行级异常策略＝跳过整行并记录；跳过成对两行后全年借贷合计仍然平衡；异常清单与运行摘要披露 2 行 |
| 日期格式混排 | "2026-01-15"、"2026/1/15"、真日期单元格、文本"20260115"并存 | 公式统一识别为日期并生成"年月"；歧义格式须先明确格式配置 |
| 前导零与大数 | 凭证号"0001"带前导零；科目编码锁定文本；个别金额超过 12 位 | 前导零保留；大额金额仍为数值且精确 |
| 列名差异 | 个别 csv 列头带空格「凭证日期 」或写作「凭证编号」 | 文件夹批量读取的字段对齐差异报告逐项呈现，不允许静默错列 |
| 伪 xls | 1 个 .xls 后缀实为分隔文本 | 按内容识别读取，不从后缀推断 |

### 2.3 画布节点清单与连线

连线总览：

```
Excel输入A[表格类文件夹]──┐
                          ├→纵向合并 Union→字段清洗 Clean→公式 Formula→分列 Split→关联 Join[J|L|R]
CSV/文本输入B[文本类文件夹]┘                                                    ↑
手工输入[科目映射表]──────────────────────────────────────────────────────────┘
J→汇总 Summarize→筛选 Filter[T|F]，T→Excel输出·大额客商
J→汇总 Summarize→Excel输出·客商汇总
J→去重 Unique[客商名称][U|D]，U→Excel输出·客商清单，D→结果区核对行数
J→字段选择 Select→排序 Sort→Excel输出·全年明细
L→Excel输出·未挂映射科目
R→结果区查看（映射表未被使用的科目）
```

逐节点关键配置：

1. **Excel 输入 A（表格类文件夹）**：文件夹路径（参数）；Sheet 取各文件第一个数据 Sheet，多 Sheet 文件按名称排除非数据 Sheet；表头行与数据起始行；来源列默认显示（来源文件、Sheet、原始行号）。
2. **CSV/文本输入 B（文本类文件夹）**：编码自动识别＋抽查手动核对；分隔符自动识别；金额列不锁定（含千分位文本）；凭证号、科目编码锁定文本。
3. **纵向合并 Union**：按字段名对齐；文本类侧缺"对方科目编码"列 → 差异报告列出，处理方式＝缺失侧补空值。
4. **字段清洗 Clean**：按字段勾选——金额：文本替换（去千分位逗号）；金额与客商：全角转半角、去不可见字符；客商：去首尾空格；整表：删除整行空记录。空文本与空值不在本节点强制合并（保持 Join 空值语义可见）。
5. **公式 Formula**：金额＝转十进制小数（清洗后文本，行级异常策略＝跳过并记录）；借方金额＝IF(借贷方向＝"借",金额,空值)、贷方金额同理（方向列"借/借方"两种写法先统一）；年月＝按格式生成"202601"样式；后续公式引用前面生成的字段。
6. **分列 Split**：凭证号形如"记-0123"拆为凭证字与凭证号序号，保留原列开关打开。
7. **关联 Join**：左＝合并明细、右＝手工映射表；关联字段配对＝科目编码（两侧均文本）；同名字段"科目名称"按确定规则保留并重命名（账面侧/映射侧各留一列）；J/L/R 三路全部接走。
8. **汇总 Summarize**：分组＝客商名称＋科目大类；聚合＝求和（借方金额）、求和（贷方金额）、总行数、去重计数（凭证号）。
9. **筛选 Filter**：条件构造器——净发生额（汇总后公式：借方合计−贷方合计）绝对值 ≥ 参数"金额门槛"（数字参数，验收取一个能筛出少量客商的值）；T 路输出，F 路在结果区核对行数。
10. **去重 Unique**：按客商名称去重，保留规则＝首次出现；U＝客商主清单，D＝重复路（仅核对行数守恒）。
11. **字段选择 Select**：为"全年明细"Sheet 选列、改序（含来源列是否带入输出的选择）。
12. **排序 Sort**：按凭证日期、凭证号排序，空值位置默认，稳定次序可重现。
13. **Excel 输出**：一个节点接多条上游连线各成一 Sheet，文件名"序时账汇总_{期间}.xlsx"（期间＝文本参数）；金额列、日期列输出格式配置；无（末端节点）。

### 2.4 预期输出与行数逻辑关系

输出文件 1 个、5 个业务 Sheet：

- **全年明细**（J 路）：行数＝12 个文件有效记录数 − 整行空记录数 − 跳过的异常行数；借方合计＝贷方合计（十进制精确相等，因成对跳过保持平衡）；按月小计同样平衡；
- **客商汇总**：行数＝按客商名称（清洗归一后）的去重计数，空客商单独一组；每客商借贷合计＝全年明细中筛选该客商后的求和；
- **大额客商**：行数＝客商汇总中净发生额达门槛的客商数，是客商汇总的子集；
- **客商清单**（U 路）：行数＝客商汇总行数；D 路行数＝汇总前明细行数 − U 行数（U＋D 守恒）；
- **未挂映射科目**（L 路）：行数＝明细中科目编码不在映射表的行数（预埋缺失的 2 个科目对应行数）；R 路行数＝映射表未被引用的科目数（结果区查看）。

### 2.5 核对方法（交叉独立基准）

1. **Excel 批量合并**：把同一文件夹交给现有工具批量合并，核对合并总行数＝「全年明细」行数＋跳过行数＋删除的整行空记录数；抽查合并结果的借方总计数；
2. **Excel 手工复算**：任选 3 个月度文件，先手工处理千分位/全角（如用替换与分列转换），再按客商筛选 SUM，与「客商汇总」逐客商比对借贷合计；抽 1 个全角括号客商、1 个空客商单独核对落组；
3. **看账工具**：导入清洗后的全年明细（或原始序时账），按科目筛选发生额合计，与「全年明细」按科目汇总交叉比对；
4. **构造侧已知答案**：数据生成时即按（客商×科目大类）预计算合计与去重凭证号数，全量比对；
5. **行数守恒核对**：J＋L＝左侧有效明细行数；J＋R＝右侧映射表行数（按行展开前口径）；汇总长表合计＝明细合计。

### 2.6 验收检查点清单（除 1.2 通用项外）

| 换第二套数据经参数确认页重跑成功；流程文件拷贝另一台电脑跑通 | 第 6、13 节 |

## 3. 验收流程二：两表核对（科目余额表 vs 辅助余额表）

### 3.1 流程目的与业务场景

往来科目审计：把科目余额表（TB）中的往来科目明细余额与客商辅助余额表逐户核对，找出余额差异、单边挂账（账有表无/表有账无），并校验辅助表自身借贷合计平衡，输出可直接放底稿的异常清单。

### 3.2 输入数据清单

| 数据 | 形态与规模 | 字段清单 | 行数量级 |
| --- | --- | --- | --- |
| 科目余额表.xlsx | Sheet"科目余额表"（另有"调整表"Sheet 需排除） | 科目编码、科目名称、客商名称（往来明细行挂客商）、期初余额、借方发生额、贷方发生额、期末余额（贷方余额以负数表示） | 百行级（含非往来科目，供筛选用） |
| 辅助余额表.xls（真正二进制 xls） | 表头不在第 1 行（前几行为标题与"单位：元"）；老式 Excel 自动转存路径验收载体 | 科目编码、客商名称、期初余额、本期借方、本期贷方、期末余额、余额方向（借/贷） | 千行级（万行级亦可） |
| 关联方客商清单 | 手工输入小表 | 客商名称、关联关系类型 | 十行级 |
| 配套序时账 | 与流程一同源，供 TBJE 完整性核对使用 | 同流程一 | 万行级 |

**故意埋入的问题数据**：

| 问题类型 | 埋法 | 期望行为 |
| --- | --- | --- |
| 客商写法差异·可归一 | 数对客商一侧"XX（上海）有限公司"全角括号、另一侧半角；一侧带尾缀空格 | 清洗（全角转半角、去首尾空格）后 Join 配对成功 |
| 客商写法差异·不可归一 | 数对客商"有限公司" vs "有限责任公司"等实质写法差异 | 落 L/R 两路，供两列模糊匹配人工确认是否并户 |
| 空客商 | TB 若干行客商名称为空（挂账未设辅助） | Join 空值键不匹配，落 L 路 |
| 重复键膨胀 | 辅助表同一（科目编码＋客商名称）出现两行（如重复录入） | J 路该组 1×2＝2 行组合；节点统计显示键重复与膨胀提示 |
| 余额方向口径相反 | TB 期末余额借正贷负单列；辅助表"方向＋金额"两列 | 公式统一为借正贷负后比较，不因口径相减出假差异 |
| 容差边界 | 差额恰好等于容差的行 1 笔、超容差若干笔 | 边界行按配置口径（含等号与否）落位，口径写入配置与规则摘要 |
| 空值余额 | TB 个别行期末余额为空（未结转） | 检查"关键字段非空"规则捕获；比较公式空值传播不误报为差异 0 |
| 类型陷阱 | 另备一份 TB 拷贝把科目编码存为数值单元格（辅助表为文本） | 提示"类型不一致先提示修正"，不静默互转 |
| 辅助表自身不平衡 | 另备一份不平衡版本（预埋 1 笔差额） | 全表借贷平衡规则失败时，辅助表全部输入记录进未通过路（演练用） |

### 3.3 画布节点清单与连线

连线总览：

```
Excel输入[TB]→筛选 Filter[往来科目][T|F]，T→字段清洗 Clean[客商]──────────┐
                                                                          ├→关联 Join[科目编码+客商名称][J|L|R]
Excel输入[辅助余额表.xls]→字段清洗 Clean[客商]→检查 Check C1[借贷平衡+编号唯一][通过|未通过]┘
J→公式 Formula[口径统一+差额]→检查 Check C2[数值区间+关键字段非空][通过|未通过]
J→关联 Join2[×手工输入·关联方清单][J|L|R]，J2→公式[标注"关联方"]
C2通过→Excel输出·核对一致；C2未通过→Excel输出·差异超容差（含违规原因列）
C1未通过→Excel输出·辅助表自身异常
L→Excel输出·账有表无；R→Excel输出·表有账无
未通过汇总→CSV输出·异常清单（GBK，演练编码异常）
F路→结果区核对行数
```

逐节点关键配置：

1. **Excel 输入 TB**：Sheet 按名称；表头行；科目编码锁定文本、金额列十进制小数。
2. **筛选 Filter**：条件构造器（且/或一层）——科目编码前缀属于应收/应付/其他往来科目集；T 路进主流程，F 路行数在结果区核对。
3. **Excel 输入 辅助余额表**：真二进制 .xls；表头行配置为实际表头所在行；余额方向、金额列类型；来源列显示。
4. **字段清洗 Clean**（两表各一）：客商名称全角转半角、去首尾空格、去不可见字符；**不**把空文本转为空值（保持空值键语义）。
5. **检查 Check C1**（接辅助表清洗后，作校验分支不作闸门）：规则①全表借贷合计一致，容差显式配置；规则②编号唯一（键＝科目编码＋客商名称）；未通过路含违规原因列与规则执行摘要；另备空输入演练（把筛选前缀改成查无此科目 → 规则摘要必须呈现空输入，不得当作检查通过）。
6. **关联 Join**：多字段配对＝科目编码＋客商名称；左右输出字段与同名字段（两表均有"科目名称"）按确定规则处理；J/L/R 三路全部接走。
7. **公式 Formula**（J 路）：辅助带符号金额＝IF(余额方向＝"贷"，−期末余额，期末余额)；差额＝TB 期末余额 − 辅助带符号金额；差异方向标签。
8. **检查 Check C2**：规则①数值区间（差额绝对值 ≤ 容差，容差显式）；规则②关键字段非空（期末余额、辅助金额）；通过/未通过两路，未通过含违规原因列（说明规则、实际值与预期值）。
9. **关联 Join2**（可选标注）：J 路明细 × 手工输入关联方清单，键＝客商名称；J2 路公式加"关联方"标签列，L2 路正常继续，R2 路结果区查看。
10. **Excel 输出**："往来核对_{期间}.xlsx"，一个节点多路上游各成一 Sheet：核对一致、差异超容差、账有表无、表有账无、辅助表自身异常；金额列输出格式配置。
11. **CSV 输出**：异常清单另出一份 CSV（编码选 GBK）；演练：客商名中埋一个 GBK 无法表示的生僻字符 → 明确报错，不得以问号替换后宣称成功。

### 3.4 预期输出与行数逻辑关系

- 筛选 T 行数＝TB 往来科目行数，F 行数＝TB 非往来行数，T＋F＝TB 总行数；
- J 行数＝按（科目编码＋客商名称）键的匹配组合展开：重复键组 J 行数＝该组左行数×右行数（预埋 1×2 组膨胀 2 行）；
- L 行数＝TB 往来行数 − 参与匹配的 TB 行数；R 行数＝辅助行数 − 参与匹配的辅助行数；
- 写法可归一对（全角括号、尾空格）清洗后进 J，**不**落 L/R；写法实质差异对与空客商落 L/R；
- 「核对一致」＋「差异超容差」行数＝J 行数；差异超容差行数＝预埋超容差笔数（含 1 笔边界行按口径落位）；
- TB 侧合计守恒：（J 路中 TB 侧余额合计）＋（L 路合计）＝TBJE 可读出的往来科目余额合计；辅助侧同理（J＋R）；
- C1 编号唯一未通过行数＝预埋重复键组的全部行（该组所有记录）。

### 3.5 核对方法

1. **TBJE 完整性核对**：用同一套科目余额表＋配套序时账跑 TBJE，先确认 TB 自身勾稽平衡、发生额一致，作为输入侧金标；再核对流程输出中 TB 侧合计（J 路中 TB 列合计＋L 路合计）与 TBJE 报告的往来科目余额一致；
2. **Excel 手工复算**：用 SUMIFS 对预埋的每一类问题行（全角括号对、尾空格对、责任公司对、空客商、重复键、容差边界、空值余额）逐笔核对落位 Sheet 与数值；L 表、R 表分别求和与源表筛选合计比对；
3. **两列模糊匹配**：把「账有表无」客商列与「表有账无」客商列交给现有工具的两列模糊匹配 → 预期"有限公司/有限责任公司"类写法差异可配对（人工确认），确属单边挂账的保持未匹配 → 用于区分"应人工并户的写法差异"与"真单边"；
4. **看账工具**：抽 1 个单边客商导入序时账查其余额构成，验证挂账真实性；
5. **构造侧已知答案**：每类预埋问题的行数与金额在构造时已知，全量比对。

## 4. 验收流程三：分组汇总分析（千万行流水打标汇总透视）

### 4.1 流程目的与业务场景

被审计单位导出的全年业务/银企流水达千万行级。审计人员需要按期间与业务分类打标签，做月度×分类的汇总与透视，形成月度趋势底稿，同时验证大表"读取→公式→关联→汇总→透视→输出"整条流程的正确性与性能。

### 4.2 输入数据清单

| 数据 | 形态与规模 | 字段清单 | 行数量级 |
| --- | --- | --- | --- |
| 流水.csv | 主档：UTF-8 带 BOM、逗号分隔（另备 GBK 版与分号版做读取对拍）；含跨行引号记录（摘要内含换行） | 交易日期、交易时间、对手方名称、对手方账号、业务类型代码、摘要、借/贷标志、交易金额、余额、渠道代码、是否冲正 | 千万行级；另出同构百万行级子集档（正确性验收用，同一流程换参数切换） |
| 业务分类对照表 | 手工输入小表 | 业务类型代码（含前导零，文本）、业务大类 | 百行级（故意缺失流水用到的 2 个代码） |
| 分月拆分子集 | 百万行级子集按月拆为多个 csv | 同流水 | 供 Excel 批量合并对拍 |

**故意埋入的问题数据**：金额含四位小数与超过 12 位的大额；对手方账号超长数字（锁定文本，不失位）；渠道代码前导零；对手方名称与余额列含空值；交易日期两种写法混排（锁定日期格式）；交易时间含时分秒（不得降级为日期）；"是否冲正"为 Y/N 布尔；后半段（采样取不到处）埋类型异常行（行级异常策略演练）；跨行引号记录（验证记录序号与物理行定位的区分）。

### 4.3 画布节点清单与连线

连线总览：

```
CSV/文本输入[流水]→公式 Formula[期间/符号金额/冲正布尔]→检查 Check[按期间分组借贷平衡][通过|未通过]，未通过→Excel输出·未通过月
                     │
                     └→关联 Join[业务类型代码 × 手工输入·分类对照表][J|L|R]
                        J→汇总 Summarize[期间×业务大类]→透视 Crosstab→宽转长 Transpose[回验]→Excel输出·透视宽表与月度长表
                        J→汇总 Summarize[对手方名称·高基数联动]→排序 Sort[合计降序]→Excel输出·对手方汇总 ＋ CSV输出[按行数分文件]
                        L→Excel输出·未分类交易
                        R→结果区查看（未使用代码）
```

逐节点关键配置：

1. **CSV/文本输入**：编码、分隔符自动识别后手动复核；列类型锁定——对手方账号、渠道代码、业务类型代码＝文本，交易金额＝十进制小数，交易日期＝日期（格式明确）；对照采样类型建议核对一遍；
2. **手工输入**：分类对照表（代码列文本类型）；
3. **公式 Formula**（多字段顺序计算，后面引用前面）：期间＝按格式生成"年月"；带符号金额＝IF(借/贷标志＝"贷"，−交易金额，交易金额)；冲正标记＝转布尔值；月份序与季度标签由期间派生；
4. **关联 Join**：键＝业务类型代码（两侧文本）；J/L/R 三路接走；
5. **汇总 Summarize（主路）**：分组＝期间＋业务大类；聚合＝求和（带符号金额）、总行数、非空计数（对手方名称）、去重计数（对手方名称）；
6. **透视 Crosstab**：行字段＝期间、列字段＝业务大类、值字段＝求和（带符号金额）；动态列命名规则明确；缺失组合填充值＝空值（便于回验口径一致；另演练一次填 0 的展示口径）；
7. **宽转长 Transpose**（回验节点）：保持不变的列＝期间；转入行的新列清单＝透视生成的全部大类列；
8. **汇总 Summarize（对手方路）**：分组＝对手方名称（高基数联动，见 5.3）；聚合＝求和、去重计数（交易日期）；
9. **排序 Sort**：按合计绝对值降序，空值位置默认，稳定次序可重现；
10. **检查 Check**：按期间分组规则——每月借方合计＝贷方合计（容差 0，显式）；未通过组该月全部记录进未通过路；
11. **Excel 输出**："流水月度分析_{期间}.xlsx"：月度汇总长表、透视宽表、未分类交易、未通过月、对手方汇总（高基数档演练按格式容量自动分 Sheet 或分文件，合计行数一致）；
12. **CSV 输出**：对手方汇总 CSV 按行数分文件（高基数档触发分片），分片不截断记录、合计行数与节点结果一致。

### 4.4 预期输出与行数逻辑关系

- 行数守恒：输入记录数＝J 行数＋L 行数＋跳过的异常行数（跨行引号不改变记录数）；
- 月度汇总长表行数＝（期间×业务大类）实际出现的去重组合数；透视宽表行数＝期间数、列数＝对照表大类数；宽转长回验行数＝长表行数（缺失填空值口径）；填 0 口径演练时，宽转长多出的组合数＝期间数×大类数 − 长表行数；
- 金额守恒：长表合计＝宽表全部格子合计＝全量带符号金额合计 − 跳过行合计；
- 未分类交易行数＝预埋 2 个缺失代码的交易行数；
- 未通过月行数＝预埋差额月的全部记录行数（分组规则整组分流）；
- 对手方汇总行数＝对手方名称去重计数（空名称单独一组）。

### 4.5 核对方法

1. **构造侧已知答案**：合成数据生成时即按（期间×大类）预计算合计、行数与去重计数；百万行级子集档做全量逐格比对；千万行档做合计守恒与分月抽格比对；
2. **宽转长回验**：透视结果转回长表与汇总 Summarize 直接输出比对（行数与合计全等）；
3. **Excel 手工复算**：抽 1–2 个月份，在 Excel 中按该月筛选（或 SUMIFS）复算该月各大类格子；
4. **Excel 批量合并**：把按月拆分的百万行级子集交给现有工具合并后手工透视，与工具输出的月度长表对拍；
5. **舍入双口径**：另搭两条汇总路对比"先逐行舍入再汇总"与"先汇总再舍入"，两者结果应不同且各自与构造侧对应口径基准一致（ROUND 中点远离零：正负各验一笔）；
6. **同构对拍**：同一子集以 GBK 版、分号分隔版再读一遍，输出应完全一致。

### 4.6 验收检查点清单（除 1.2 通用项外）

| 检查点 | 设计文档依据 |
| --- | --- |
| 千万行整条流程（读取→公式→关联→汇总→透视→输出）跑完，不是只验证读取 | 第 1、13.1 节 |
| 预览运行快速试跑、常驻横幅、不落盘；埋错在采样外 → 预览通过、全量触发异常（行级异常策略与披露） | 第 7、9 节 |
| 跨行引号记录：记录序号与物理行定位区分正确，记录数不因换行膨胀 | 第 4 节 |
| 交易时间保留时分秒，不无提示降为日期；日期格式歧义须先明确配置 | 第 9 节 |
| 全量运行进度：总量已知时显示已处理行数与耗时；透视等阶段显示阶段状态、不伪造百分比；中途取消 → 已完成节点结果保留、未完成缓存不发布 | 第 7 节 |
| 分片输出不截断记录，各分片合计行数与节点结果一致，分片以完整文件集合及清单记录状态 | 第 7、10 节 |
| 统计按需计算：数值列合计须点按钮才算；结果区搜索/排序不改变下游（查看后重跑对比） | 第 8 节 |
| 超长账号不失位、前导零保留、大数仍为数值、四位小数不截断 | 第 9 节 |
| 透视缺失组合填充值配置生效；动态列命名规则明确 | 第 4 节 |
| 增量重跑：只改透视值聚合方式（求和改最大）→ 复用上游，仅透视及下游重跑 | 第 7 节（首版承诺） |
| 性能标定记录（按设计文档 13.3 字段）：机器配置、输入文件字节数与行列数、分组数量与键重复率、首跑/缓存重跑/导出耗时、峰值内存、临时空间峰值、取消响应 | 第 13.3 节 |
| Parquet 输入演练：把工具箱自身缓存格式作为输入再读，同一流程输出与 CSV 输入版一致 | 第 4、10 节 |
| 换百万行/千万行两档参数切换重跑；流程文件跨机跑通 | 第 6、13 节 |

## 5. 规模验收场景测试数据构造方案（对应设计文档 13.1）

通用要求：以下场景均须按设计文档 13.3 记录性能标定（CPU、内存、磁盘类型及剩余空间；输入文件字节数与行列数；分组数量、键重复率与关联输出规模；流程与工具版本；是否已有缓存；首跑、有效缓存重跑与导出耗时、峰值进程内存、临时空间峰值、取消响应）。构造侧一律预产已知答案。占比为构造目标值，验收记录登记实际值。

### 5.1 大表关联

**构造要求**：

- 两表规模：左表千万行级（明细表），右表两档——千万行级（真正"两张大表"主场景）与百万行级（"大表×映射/维表"辅场景），两档都要跑，不得只用大表×几十行小表替代；
- 键分布（左表口径）：与右表共有的可匹配键约 60%（其中约四分之一为重复键，左侧重读度 2–3 行/键）；仅左侧键约 20%；空值键约 5%；单侧空文本键约 2%（埋在左、右侧不出现同值，预期落未匹配）；极高重复度压力键约 3%（单键两侧各上千行，组合达百万至亿级，用于验证"明显超出资源预算时明确停止并给出处理建议"）；其余为常规唯一键；右表按对称口径构造（仅右侧键约 20%）；
- 键类型：文本键为主；另备一小撮"左文本右数值"类型不一致键，验证提示修正而非静默互转；
- 携带金额列（多小数位、正负混合）与排序/序号列（供保留规则与回验）。

**验收核对方法**：

- 构造侧按键分组预计算：J 行数＝Σ（共有键左行数×右行数）、L 行数、R 行数、膨胀率＝J/左表行数，与实际输出逐项比对；
- 利用 J 路保留的左右来源标识：按左来源标识去重后应恰等于左表匹配行集合（行数与金额合计一致），右侧同理；
- 合计守恒：左表金额合计＝左匹配行合计＋L 合计；右表同理；
- 压力键场景预期明确停止并给出处理建议，节点统计呈现膨胀提示；
- 对照设计文档验收重点：J/L/R 正确、多对多组合数量可核对、资源边界有效、大表执行时内存受控（以 13.3 数值为准）。

### 5.2 全局排序与去重

**构造要求**：

- 单表千万行级，且**拆成多个文件组成文件夹**（跨文件重复，验证全局处理而非文件内处理）；
- 去重键构成：唯一键约 50%；重复 2 行约 25%；重复 3–5 行约 15%；全字段完全相同行约 5%；空值键约 3%；空文本键约 2%（与空值不同组）；
- 保留规则可判定：每行带序号/时间戳列，同一键多行序号递增、金额不同 → 保留"首次出现"应取文件顺序＋文件内行序最先的一行，"最后一次"取最末；同键行刻意分放在不同文件；
- 排序键设计：主键高基数近唯一（交易日期时间）、次键高重复（客商名称）、第三键散布空值；相同全键组内埋原始序号列验证稳定次序；
- 文件夹内文件顺序确定（按名称），保证重跑可重现。

**验收核对方法**：

- U＋D 行数＝输入总行数；U 行数＝去重键分组数（空值键一组、空文本键另一组）；构造侧按键分组计数全量比对；
- 首次/末次两种保留规则各跑一遍：同键多行组内两版结果互补（除单行键），抽取高分键组逐行核对保留行正确；
- 相同全键组两次运行次序一致且与首次出现顺序一致（稳定次序）；
- 换保留规则重跑、换文件顺序重跑（改名后）均与构造基准一致。

### 5.3 高分组数量汇总与透视

**构造要求**：

- 千万行输入两套分组设计并行构造：**少量分组键**（分组数个位至两位数，如期间×大类，每组百万行级）与**大量分组键**（分组键基数百万级，如对手方名称，长尾分布：头部极少数客商占约半数行、尾部大量单次客商）；
- 金额设计：四位小数、正负混合、空值金额约 5%（求和跳过空值、平均以有效值为分母）、超过 12 位大额若干；构造侧按组预计算两套口径基准——"先逐行舍入再汇总"与"先汇总再舍入"；
- 分组键空值行为：分组键为空值的行成一组统计，空文本为另一组；
- 透视列字段基数两档：几十列（常规）与上千列及以上（压力）；行×列大量缺失组合（稀疏），缺失组合填充值显式配置；
- 超限构造：列字段基数构造超过输出表格列数上限 → 预期明确报错，不静默丢列。

**验收核对方法**：

- 少量分组场景：与构造侧逐组基准全量比对（行数＝分组数、每组合计、非空计数与去重计数区分核对）；
- 高分组场景：全表合计守恒（全表金额合计＝Σ组合计）、键分组计数分布与构造基准对拍、头部与尾部各抽若干组逐笔复算；
- 两种舍入口径分别与对应构造基准一致，两口径结果应不同；
- 透视：行列合计与长表一致、稀疏组合填充口径正确、超限场景明确报错；对照验收重点：与普通小分组汇总分别测试、精度正确、内存受控（13.3 数值）、超出列数/资源边界明确失败。

### 5.4 客户 .db 实际输入

**构造要求**：

- 格式前提：以客户实际交付 .db 脱敏样本确认内部格式后，在**已识别格式**上构造千万行级场景（未识别格式前不得记为验收通过）；
- 库内多表（至少三张：主交易大表千万行级、维表、小表），验证列表→选表→选字段读取路径；
- 字段类型全覆盖：文本、整数、十进制、**浮点**（浮点字段不得被静默宣称为精确十进制，转换方式须披露）、布尔、日期、日期时间、空值、超长数字文本、大金额；主键表与无可稳定顺序表各一张（后者演练去重时要求选定排序键）；
- 诊断样本四件套：正常、未知格式（异格式改名文件）、加密、损坏（截断）各一份，诊断信息分别明确；
- 活跃副本场景：复制自运行中系统的库文件可能带伴随文件，须验证读取一致性与重跑缓存身份（不得只对主文件取指纹）。

**验收核对方法**：

- 同内容双格式对拍：同一份数据同时构造 .db 版与 CSV 版，两路跑同一流程，输出行数、合计、去重计数应完全一致；
- 构造侧基准：表行数、各列合计/非空计数/去重计数已知，全量比对；
- 类型保留核对：浮点字段的披露口径、超长数字不失位、日期时间不降级；
- 整链路验收：识别→列表→选表选字段→公式/汇总→输出，并按 13.3 记录性能；诊断四件套逐一核对提示语。

### 5.5 表格兼容矩阵

**构造要求**：

- 制作一份**标准样表**，覆盖：全部字段类型（文本/整数/十进制/布尔/日期/日期时间）、前导零编号、千分位文本金额、全半角混写、空值/空文本/仅空格文本、超 12 位大数、多小数位、多 Sheet、表头不在首行、非数据 Sheet；
- 将标准样表分别导出为：xlsx、xlsm、真二进制 xls、xlsb、ods、伪 xls（分隔文本版与 Excel 2003 XML 版各一）、csv（GBK / UTF-8 带 BOM / UTF-16）、tsv、txt、Parquet；
- 大文件路径：大 xlsx（百万行级）多文件多 Sheet 汇合流程；老式 xls 三路径（本机有 Excel 自动转存成功且源文件不替换 / 模拟缺 Excel 提示人工另存 / 转存失败明确报错）；伪 xls 两路大样本。

**验收核对方法**：

- 每种格式跑同一条迷你流程（输入→字段选择→汇总→Excel 输出），以 xlsx 版为金标对拍：行数、字段数、类型判定、合计、去重计数应全等，差异逐项记录；
- 格式支持以**逐项记录**为准：未验证的识别路径不得记成验收通过；记录每格式的通过与限制；
- 老式 xls 三路径与大文件路径按上述要求分别演练并登记结果。
