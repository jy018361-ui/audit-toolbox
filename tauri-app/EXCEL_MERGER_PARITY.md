## 2026-09-24 · 智能表头匹配·外部审计修复（数据安全两项 + 交互八项）

**外部产品审计发现 10 项问题，全部核实属实并修复；以下是行为口径变化。**

- **独立列槽位化（防静默丢数据/覆盖）**：未匹配列的落位不再按名字反查，改为
  「计划 assignment 下标 + 源列下标 → 独立列下标」的槽位映射。修复三个场景：
  同文件重名列互相覆盖、手动移入未匹配区的模板同名列整列被丢、跨文件同名
  合列后残留永远为空的「备注(2)」占位列。与模板列同名的独立列加「(独立)」后缀。
- **合并前表头快照复核（防预览后文件被改）**：合并执行时逐文件把当前表头行
  （按计划层数拍平）与预览快照比对，列名或列数不一致报 `HEADER_PLAN_STALE`
  并中止，不再按旧列位错排落盘；XLSX 与 CSV/文本路径均覆盖。
- **对立词补齐**：原币/本位币、含税/不含税 补进强制拦截清单；「不含税」包含
  子串「含税」，判定改为超集词优先（命中长词不算命中短词）。
- **修正表头行后自动重跑匹配**（新 `excel_merger.rematch`）：人工改表头行/层数
  后按新表头重跑机器匹配，之前人工配对按「源列名→目标列名」能对上的自动恢复，
  不再从白纸重连。
- **个人对照表可管理**（新 `excel_merger.alias_list` / `alias_delete`）：规则页
  「我的对照表（N）」弹层查看与删除，拖错又勾了记住的条目能清掉。
- **合并失败可返回网格**：网格常挂载（hidden 而非卸载），任务失败后错误区出现
  「返回匹配网格调整」，人工调整全部保留，改完直接重试。
- **外部模板切走可切回**：上传过的外部模板保持在模板下拉里。
- **重名列可区分**：格子上标注源列位（如「金额 E」）；顶部固定操作说明一行。
- **统计口径修正**：人工移入未匹配区的列计入「未匹配」而不是「匹配」。
- 未做（后续）：对照表按客户/项目分组。
- 回归：`cargo test --manifest-path src-tauri/Cargo.toml --lib excel_`（44 项，
  含重名列/跨文件同名/快照不符三组新回归）；前端
  `npx vitest run src/components/HeaderMatchGrid.test.tsx src/ExcelMergerPage.test.ts`；
  真实样例 `cargo test --test header_match_je_probe -- --ignored`。

## 2026-09-23 · 智能表头匹配（纵向合并可选增强，默认关闭）

**这是全新增量能力，旧 Python 基线没有对应功能，不存在迁移差异；以下记录行为口径。**

- 开关关闭（默认）时纵向/横向/多 Sheet 三条路径行为与此前完全一致（含"保留每个输入的表头行"旧口径）。
- 开关开启且纵向单表合并时：默认以第一个输入文件为模板（可切换为其他输入或上传只借表头的外部模板），
  自动识别每个文件的表头行（含表头不在首行、两层合并表头拍平成单层，两层判定依赖 XLSX/XLS 的合并单元格信息），
  按模板表头对齐各文件列：名称归一化一致/个人对照表/常用同义写法/表头分段一致 为机器绿直接采信；
  相似度（编辑距离+LCS+bigram 加权）只给黄色建议；对立词（借方/贷方、应收/应付、期初/期末等）相似度再高也拦下。
- 前端匹配网格（一行一文件、对齐即匹配、右侧未匹配区）人工调整支持拖拽与右键菜单双通道，
  冲突直接交换可撤销，确认前可整列剔除、修正表头行、丢弃列；匹配结果全部落「匹配日志」Sheet（仅 XLSX 输出）。
- 合并输出在匹配模式下固定为「来源文件 + 来源Sheet + 模板列 + 独立列（跨文件同名合一）」，
  只保留一行表头、分表时重写表头；缺映射计划的输入文件直接报错要求重做预览，绝不未重排就落盘。
- 个人对照表落 `%LOCALAPPDATA%` 数据目录 `header_aliases.json`，仅存人工确认过的配对；读取失败静默降级。
- 未实现（后续增强）：LLM 兜底复核、横向合并同名列去重、金额格式差异提示、CSV 输出的匹配日志（CSV 无日志页）。
- 回归：`cargo test --manifest-path src-tauri/Cargo.toml --lib excel_`（含匹配引擎 12 项 + 合并端到端 4 项）；
  前端 `npx vitest run src/components/HeaderMatchGrid.test.tsx src/ExcelMergerPage.test.ts`。

## 2026-09-04 · XLS 文本导出兼容

- 真正的二进制 XLS 仍走 Calamine；新增由桌面 Excel 生成的无业务数据 BIFF8 样例 `tests/fixtures/Excel Merger/simple-biff8.xls`，验证大写后缀、中文 Sheet、前导零及数字与文本型 XLS 混合合并。
- `.xls` / `.XLS` 增加有限文件头探测：排除 OLE、ZIP、HTML/XML、异常控制字符后，按分隔文本特征读取。支持 GBK、UTF-8（含 BOM）、带 BOM 的 UTF-16LE/BE；不代表支持所有以 XLS 命名的格式。HTML/XML、加密和损坏工作簿没有新增解析器。
- 文本纵向输出 CSV/XLSX 改为流式解码、逐记录写出；CSV 中的真正 Excel 文件逐文件加载，不再一次装入全部输入。横向合并仍需全量装载，真正 Excel 工作簿仍受读取库的内存使用约束。
- 保留输入顺序、每个输入的表头行、来源文件/Sheet 列、前导零和文本金额；CSV 允许不同输入列宽。保留历史文本来源 Sheet 标记 `CSV`。
- 文本解析/编码中途失败时，纵向任务整体失败并删除临时输出，避免发布截断文件；不再用有损解码静默写入乱码。编码根据有限样本判断，混合编码不保证兼容。
- 文本型 XLS 在多 Sheet 模式先逐记录生成临时 XLSX 数据表再复制；它本身不含可保留的原始公式/样式。全工具共享读取与模板准备范围见 [XLS 输入兼容范围](XLS_INPUT_COMPATIBILITY.md)。
- 全部读取失败时显示具体文件原因；检查列表区分“分隔文本”“读取失败”；失败/取消隐藏满格进度条。
- 回归：`cargo test --manifest-path src-tauri/Cargo.toml excel_merger::`；覆盖多编码、跨缓冲区字符、引号内换行、取消、晚发解码错误清理、真实 BIFF8 和格式拒绝。前端：`npx vitest run src/ExcelMergerPage.test.ts`、`npm run build`。

基线：`modules/Excel-Merger/batch_merger.py`（1,870 行，tkinter + 多引擎可插拔）。
目标：`src-tauri/src/excel_merger.rs` + `excel_com.rs`，前端为 `App.tsx` 内的 `ExcelMergerPage`。

**这是九个工具里最后才建立对照记录的一个。** 在 2026-08-05 之前它没有任何迁移文档，
而 `excel_merger.rs` 同时还是全部重任务的统一调度器，改动波及面比其他工具大。

## 2026-08-05 已修复

- **读取失败的文件清单算了但不显示**：引擎一直生成 `warnings`，通用结果组件只认"消息/计数/输出路径"三类字段，
  从不渲染它。合并 50 个文件、其中 8 个因加密未合入时，界面显示绿色"处理完成。"，
  用户会拿着缺 8 个文件的底稿去做抽样与小计。现已渲染。
- **失败时结果区仍显示"处理完成。"**：失败事件也带结果对象，被当成成功渲染，
  红色错误横幅下方紧跟一句绿色"处理完成。"。现失败/取消不再渲染结果。
- **超链接超过 Excel 上限会产出需"修复"的文件**：每张工作表最多 65,530 个超链接，
  旧版所用写库自带该检查并静默跳过多余链接（文件仍可正常打开），新版写库不检查、照写不误。
  这是本次审计中**唯一可能产出坏文件**的差异，且触发条件（大批量明细账 + 默认勾选的超链接）
  正是该工具的主力场景。现超出后自动降级为纯文本并给出警告。
- **默认 Sheet 范围改变导致静默少合数据**：旧版只要清单含 Excel 就**必然**弹出 Sheet 选择窗且默认全选，
  一路回车即"合并所有工作表"；新版默认停在"每个文件仅取第一个 Sheet"。
  同样的操作习惯，数据少一截、且因未进入匹配模式而少一列"来源 Sheet"，列位置整体左移。
  默认值已改回"合并所有 Sheet"。

## 已知差异（保留新版行为，但需知晓）

| 场景 | 旧版 | 新版 |
| --- | --- | --- |
| 日期列（纯 xlsx 清单、纵向、输出 xlsx） | 显示为 `45292` 这类序列号 | 正确显示为日期。**结果确实变了**，按数字读该列的下游宏/查询会失配 |
| 工作表名 | 全 xlsx 清单为 `Merged`，混入 .xls/.csv 时变 `合并结果` | 一律 `Merged`。按表名引用的跨表公式在混合清单场景会断链 |

| 超 104 万行 | 全 xlsx 通道拆表；混合清单通道**不拆也不报错，静默丢弃超出行** | 恒定拆表 |
| 超 16,384 列 | 静默丢弃多余列 | 明确报错，不产出文件 |
| 文本文件 | 只试 UTF-8 / GBK，一律按逗号分列 | 识别 UTF-16、BOM，嗅探逗号/制表符/分号。制表符 txt 由"挤在一列"变为正确分列 |
| 编码坏掉的文本文件 | 跳过并在完成提示中告警 | 严格解码；纵向中止并清理临时输出，横向跳过并告警 |

## 仍未清零

- **多 Sheet 模式的 Excel COM 原样复制这条路，持续集成从未覆盖**：
  需真机 Excel 的 `excel_com_preserves_formula_and_sheet_order`（在 `excel_merger.rs`，默认 `#[ignore]`）从未进入常规回归，发布门禁的冷启动验收也不含多 Sheet 模式；`excel_com.rs` 内唯一的测试是纯字符串断言，覆盖不到 Excel 进程生命周期。
  这是一段涉及 Excel 进程生命周期管理的代码，任何重构或依赖升级都可能悄悄弄坏它而门禁照常放行。
- **打开源工作簿时未传"只读"与"不更新链接"**：旧版明确传了；理论后果是独占打开与外部链接被刷新，需真机验证。
- **多 Sheet 模式下单个文件读不出即整体失败**（单表模式只记警告并跳过），错误提示还吞掉了文件名。
- **横向合并仍全量装载**；纵向文本已流式处理，真正 Excel 的内存仍取决于单个工作簿大小。
- **大文件超链接规模预警（三选一）整体缺失**：旧版会估算行数、体积、耗时并让用户在"保留超链接/关闭以加速/取消"间选择。
- **不能自定义输出文件名**（后端支持 `outputPath`，前端只传目录）。输出**目录**已在添加文件后自动填成
  第一个输入文件所在目录并显示出来，手选目录后可「恢复默认」改回；文件名仍由后端按 `Excel合并结果_<日期>_<时间>` 生成，界面只在提示里预告。
- **文件列表不能多选移除**。
- 前端 442 行**没有任何测试**，上述三条已修问题全部出在这段代码里。
