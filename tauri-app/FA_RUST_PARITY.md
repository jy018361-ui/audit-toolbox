# FA List Rust 迁移覆盖矩阵

本矩阵以 `tools/fa_list` 的 Python 内核与 `audit_engine/handlers.py` 的实际生产路由为基线。Rust 实现在 `src-tauri/src/fa.rs`，生产路径不调用 Python、PowerShell 或 Excel COM。

## 仍需正式样例验证/补齐后才可宣称完全等价

### 2026-08-09 长期资产明细新旧输出对比

- 对比文件：旧版 `旧代码输出-FA_List_20260808_213955.xlsx`，新版 `新代码-FA_List_20260809_135119.xlsx`。两者 Sheet 集合一致，期末 FA List 均为 5,499 张，原值 871,318,110.94、累计折旧 251,439,019.31，说明期末读取与金额主干一致。
- 核心差异不是计算公式，而是期初工作表不同：旧版读 `固定资产明细 241231`（5,449 张），新版误选首页 `Data`（6,295 张）。因此新版将 842 张仅期初卡片识别为处置，处置清单从 26 行/85,627.81 放大到 842 行/196,013,728.80；合并数据从 5,526 条业务行增至 6,343 条。
- 新增清单旧版 998 行/556,193,229.24，新版 983 行/236,705,749.54，也主要受上述期初 Sheet 口径变化影响；不应以此样例直接判定净增额逻辑有误。
- 公式数量方面，Rust 为 5,499 行 FA List 全量写入 8 列折旧测算公式（43,992 个），旧版只有 80 个；这是现有大表阈值下的有意行为，不是卡片值差异。新版数值单元格增多、文本单元格减少，是为了保持可求和类型；样式 ID 数字不可跨生成引擎直接比较，但冻结、筛选、数值/百分比格式均存在。列宽按显示内容重算，多处比旧版宽 1–4 个字符，未发现金额列低于内容宽度。
- Rust 修复：自动选表加入业务表名/期间亲和度；点分隔日期统一为 ISO；本年折旧、新增方式、新增日期仅在文件2映射和 LLM 复核中生效。真实期初样例回归已确认重新选中 `固定资产明细 241231` 且读取 5,449 行。

## 经真实样例核对后有意偏离旧版的口径

以下三处 Rust 与旧 Python 输出**不同且不应对齐**——旧版在真实样例上被证明有缺陷。改动前请先读这一节。

| 项 | 旧版行为 | Rust 行为 | 依据 |
|---|---|---|---|
| 新增清单收录范围 | 只收 `数据来源=仅文件2`，金额取期末原值全额 | 按净增额收录（含期初原值为 0 却匹配上期初卡片的行） | 旧版明细合计比自己的变动汇总表少 615 万；Rust 现为分毫勾稽 |
| 重复匹配键的原值增加 | 同一「编号+名称」多张卡片只有首条计金额，其余留空 | 每张卡片各计各的金额 | 旧版列出 4 行只算 1 行，属去重未尽；留空行无法与凭证抽档对应 |
| 数据透视表/折旧期间的合计行 | 源卡片的「合计」行被当作一个资产类别 | 计入汇总备查，不进聚合 | 旧版把整表期初原值重复计一倍（本样例 30.15 亿） |

真实样例（南昌海立 2024/2025 卡片）核对结果：变动汇总表 11 个类别全部满足 `期初+增加-减少+重分类=期末`，原值残差 0；期初余额已回到期初类别（运输设备 13,196,180.72、重分类 −11,967,221.53），与旧版逐格一致；新增清单明细 444,322,720.55 与汇总表本期增加完全相等；数据透视表合计行与变动汇总表期初/期末原值、累计折旧四项逐格相符；FA List 原值 3,247,966,584.85、累计折旧 1,748,849,343.39 与旧版一致。

复跑该样例（需本机卡片，不在仓库内）：

```bash
FA_SAMPLE_DIR=<两张卡片所在目录> cargo test --manifest-path src-tauri/Cargo.toml regenerate_sample_export -- --ignored --nocapture
```

验收结果不再在文档里写死数字——它每加一个测试就过期一次，此前 FA/Roll Forward/WP 三份记录的数字全部与实际对不上。请直接运行：


## 2026-08-05 迁移差异审计与修复

本轮对九个工具做了逐项"旧版 vs 新版"审计，结论按"功能没了 / 结果可能不一样 / 少了提醒 / 本来就该丢掉 / 新版更好 / 光看代码说不准"六类归档。
以下只记录**本工具**已落地的修复；**尚未用真实脱敏底稿验证**，所有"已修复"仅代表通过了合成回归。

### 已修复

- **折旧测算"本年应计提月份"公式**：新版曾简化为"入账次月至资产负债表日的月数、截到 12"，已提足折旧的老资产也会算出 12 个月，整块折旧测算产生巨额假差异。已改回旧版的三区间求交（资产折旧期 ∩ 本年度 ∩ 资产负债表日/处置日），并恢复月折旧额的 ROUND(...,2)。
- **合计/小计行混入明细页**：旧版从合并数据、FA List、新增清单、处置清单四张明细表整行剔除，新版只在汇总口径排除。已扩展到四张明细表。
- **累计折旧记负数时净值算反**：FA List 与变动汇总表的净值均改为对累计折旧取绝对值。
- **纠偏静默发生**：残值率、使用寿命的自动换算会改数，旧版每次弹框要求复核，新版无声。现产出警告文本并在界面展示。
- **重复匹配键无提示**：引擎一直在统计，界面从不显示，现已呈现。
- **输出路径留空即静默写盘**：曾改为弹保存对话框；2026-08-09 再改为**选定期末文件后就把默认落点（期末文件目录 + `FA_List_<日期>_<时间>.xlsx`，与 `fa::output_path` 同口径）填进输出框**，导出不再弹框——写到哪在点导出前就看得见，用户仍可「选择」改到别处或「恢复默认」改回来。时间戳在点击导出时按当前时间重算（`faDefaultOutputPath`，前端测试覆盖）。
- **自动选表会选中隐藏工作表**：字段更齐全的隐藏旧版本表可能被选中且无任何提示。现只在可见工作表中挑选（整本皆隐藏时回退全部，避免挡死用户）。
- **匹配键识别丢失旧版三层兜底**：旧版除逐字匹配 9 个中文词外，还认"含资产/卡片语境 + 含编号类字样"（700）、单独含"编号"（300）、单独含"编码"（280）。迁移时被砍，`资产序号`、`设备编号` 这类列名直接不算候选。已按同样分档补回，排在词表命中之后。
- **LLM 复核请求缺参数**：旧版每次结构化调用都下发 `thinking:{type:disabled}` 与（DeepSeek 下）`response_format:{type:json_object}`，迁移时两个都漏了。推理型模型因此先跑思维链再吐 JSON，请求必然超时；实测补上后同一端点从 60 秒超时降到约 2 秒。默认超时同时由 30 秒提到 120 秒。
- **LLM 错误信息不可诊断**：原实现先解析 JSON 再判 HTTP 状态，网关 HTML 错误页、限流纯文本与截断响应统统变成一句"网络请求失败"，非 2xx 且响应体非 JSON 时永远走不到报状态码那一行。改为先取文本、再判状态、最后解析，并区分超时/连接失败，超时提示带上当前设置的秒数。

### 与旧版的已知口径差异（保留新版行为）

- 匹配键识别新增英文词（`coding`/`code`/`assetid`/`assetnumber`）并引入数据驱动打分（唯一率、覆盖率）。**同一份文件两版可能选出不同的匹配键**：例如 `资产编码` 全为 `0000`、`资产编码.1` 为真实卡片号时，旧版按"同分取最左"选前者，新版按唯一率选后者。跨年度沿用旧版匹配键清单前需核对。
- 匹配键自动忽略首尾空格与全角空格（旧版不处理）。
