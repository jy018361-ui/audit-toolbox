## 内存与磁盘分流

两侧文件共同参与 `disk_table::should_use_disk(paths, 2)` 的工作集估算，基础表内存估算再乘两倍算法开销，含文本体积、XLSX 解压后的工作表体积以及当前机器的动态内存预算；任一文件达到公共强制阈值或估算超过安全预算时进入磁盘路径。测试可用 `__forceDisk` 让小样本执行同一分支。旧版 XLS/ODS 大文件的公共流式读取尚不支持时明确报错，提示另存为 XLSX/CSV，不回退整表读取。

识别入口在大文件分支只读取前部预览记录，不为了统计行数加载全表。`previewOnly: true` 表示 `rowCount` 是已预览数据行数，正式任务的 `summary.rowsA/rowsB` 才是完整统计；小文件保持原识别总行数。

## 行为矩阵

| 既有行为 | 当前 Rust 保留方式 | 验证 |
| --- | --- | --- |
| 归一化、繁简转换、公司/人名/地址/通用四类规则 | 两条路径共用 `prepare_row`、`score_pair` 和内嵌词表 | `磁盘文本与xlsx匹配逐候选等价` 与原归一化/评分测试 |
| 标题行、双层表头、指定列 | 预览沿用原表头判断和 `pick_column`，正式流式扫描只持有当前行及所选列；整行空白跳过，选中列为空但其他列非空的记录保留 | 磁盘等价测试包含空值列及其他列 |
| B 列 bigram 粗筛 | B 原值及 bigram 倒排索引写 SQLite；A 当前 bigram 写临时表，SQLite 完成命中聚合和排序，临时页使用磁盘 | 等价测试及候选上限测试 |
| 三倍长度差过滤及简称包含豁免 | 按命中数降序、B 原始行号升序，依次应用相同长度过滤后截取 200 个候选 | `候选同分排序与二百上限保持且分页导出完整` |
| 评分明细、疑似/自动阈值、topK 及同分顺序 | 共用评分方法；精算候选总量有界，最终仍按总分降序、B 行号升序 | 等价测试逐候选比较 JSON 和比较次数 |
| 取消、暂停、任务失败 | 公共流式读取检查取消；匹配分批检查暂停；先写临时结果，成功后事务替换正式库，失败不发布半成品 | `已取消任务不覆盖既有结果` |
| 人工确认与跨会话恢复 | 原结果和确认表结构保持；新增完整统计表，结果支持 `offset/limit/level/onlySuspect/band/onlyPending`；确认只返回本页记录 | 原 roundtrip 测试、大结果分页测试 |
| 完成事件与结果分页 | 磁盘完成事件最多返回首 200 行及全量统计；`total/offset/limit/hasMore` 标明分页；单次请求最多 1000 行 | 候选/分页测试，`五万行get_results耗时基线` |
| 全部结果、疑似确认记录、未匹配清单三张表 | 按 A 行号游标分批读取 SQLite 及相应确认，继续使用常量内存 Excel 写出，不受前端当前页影响 | 原导出确认测试，尾页确认导出测试 |

## 尚未承诺的范围

- 识别预览不承诺精确全表行数；正式匹配仍需扫描两侧全部记录。
- 超大 XLS/ODS 须转为公共流式读取支持的格式。
- SQLite 粗筛保留原算法候选语义；大量相同 bigram 仍需磁盘聚合和排序，不能承诺所有数据分布下固定耗时。
- Excel 单张工作表有行数上限；超限导出仍由写入库报错，不自动截断结果。
