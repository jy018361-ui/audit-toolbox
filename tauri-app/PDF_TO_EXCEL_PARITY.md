# PDF_TO_EXCEL_PARITY —— 回函 PDF 转 Excel

来源基线不是旧 tkinter 栈（旧栈没有此工具），而是 2026-08 交付的桌面独立版
《回函转Excel》（`C:\Users\lenovo\Desktop\回函转Excel工具\converter.py`，pdfplumber + openpyxl），
其算法已在真实回函上验收过。本文件记录工具箱 Rust 版（`src-tauri/src/pdf_to_excel.rs`）
与该基线的逐项对照。

- 前端：`src/PdfToExcelPage.tsx`（分类"效率工具"，徽标"函"）
- 任务方法：`pdf2excel.convert`（job 通道，worker 进程内执行，可取消/暂停）
- 运行测试：`cargo test --manifest-path src-tauri/Cargo.toml pdf_to_excel`
- 真实回函端到端（本机有样例时）：`cargo test --manifest-path src-tauri/Cargo.toml 真实回函端到端 -- --ignored`

## 算法对照（保留项）

| 环节 | 独立版（Python） | 工具箱版（Rust） | 一致性 |
|---|---|---|---|
| 表格检测 | `find_tables(vertical="lines", horizontal="lines")` | `Strategy::Lattice`（等价移植，经真实样例比对输出相同） | 一致 |
| 越界矩形防御 | `page.crop((0,0,w,h))` 后检测 | `page.crop(BBox)` 后检测 | 策略一致；**对象过滤语义不同，见有意差异 6** |
| 正文提取 | 表格外区域 `extract_text_lines()`，排除全部表格 bbox | `outside_bbox` 链式排除后 `extract_text_lines()` | 一致 |
| 表格清洗 | 表头前"非空单元格≤1"的行拆回正文；首个"非空列数 ≥ max(2, 列数一半)"为表头 | 同规则（`clean_rows` 纯函数） | 一致 |
| 跨页续表 | 表头签名（过滤空列）相同 + 前表贴页底/本表贴页顶 → 合并不重复表头；**不比较列数** | 同规则（`Pending` + `header_sig`） | 一致 |
| 折行代码直连 | 分段全匹配 `^[A-Z0-9,./()+\-]+$` 且含数字 → 直连（ISIN 等） | 同规则（`is_code_segment`） | 一致 |
| 金额 | `_MONEY_RE` 文本转 float + `#,##0.00;(#,##0.00)` 格式 | 同正则 + 同格式串 | 一致 |
| 前导零保护 | 账号 0100684742 保持文本 | 同规则 | 一致 |
| 空行分隔 | 仅新表前空一行；续表直接接上（不产生 294 空行问题） | 同规则 | 一致 |
| Sheet 结构 | 单一工作表「回函内容」，正文 A 列、表格内联，无合并单元格 | 同结构 | 一致 |
| 表头样式 | 加粗 + 浅蓝底纹 DDEBF7 | 同色值同加粗 | 一致 |
| 列宽 | A=70，其余 16（2..40 列） | 同（0 列 70，1..39 列 16） | 一致 |
| 批量清单 | 处理清单.xlsx：文件名/状态/页数/正文行数/表格数/数据行/输出/失败原因 | 同列同表头样式 | 一致 |
| 扫描件检测 | 第一页提取不到文字 → 明确报错"只支持文字版 PDF" | 同检测同文案 | 一致 |
| 单份失败 | 不影响其余，状态记入清单 | 同（全部失败时任务报错并带全部失败明细） | 一致 |

## 有意差异（与基线不同，均已注明原因）

1. **括号负数修复**：独立版 `_to_value` 先 `lstrip("-")` 再 parse，`(1,234.00)` 会被转成
   **正数** 1234（基线缺陷，渣打样例余额全为 0.00/正值故未暴露；独立版源码已同步修复，
   exe 需重打包才生效）。Rust 版保留负号，`(1,234.00)` → -1234，负数部分按 `(#,##0.00)`
   括号样式显示。金额符号对审计不可接受出错。
2. **输出目录**：独立版固定在 exe 旁「转换结果\时间戳\」；工具箱版由页面选择输出文件夹，
   留空则集中到第一份 PDF 旁「回函Excel输出\时间戳\」。
3. **同名冲突**：工具箱版对同名 PDF 追加序号（`样例-2.xlsx`）；独立版同目录批量会互相覆盖。
4. **进度粒度**：独立版每页回调（本机轮询）；工具箱版走 job 事件流，按累计页数推进度、
   每 20 页节流 + 每份文件必发，页面消息仍显示"第 x/y 页"。
5. **表格引擎**：pdfplumber Python 0.11 → Rust crate 0.3（lopdf 后端），同族算法的独立实现；
   行为对齐以真实样例端到端断言兜底（见下）。
6. **crop 的对象过滤语义（修正独立版两个输出缺陷）**：两版都先 `crop` 到页面边界再检测表格，
   但 Rust crate 的 crop 按**对象中心点**过滤——画到页外的矩形被丢弃，表格 bbox 回到真实边界；
   Python 的 crop 保留越界对象并把表格 bbox 钳制到近整页，正文被大框卷进表格再"拆回"，
   产生两个缺陷：①"整页巨行"——每页正文挤进一个单元格（违反"PDF 一行对 Excel 一行"）；
   ②页底信头地址被拼成假数据行混进账户数据。Rust 版这两种内容都逐行进正文流。
   298 页渣打样例逐页比对结论：286 页独立版各多 1 行信头垃圾行、5 页完全相同、无任何一页
   Rust 少真实数据；账号种类两版同为 723 种、数值单元格集合独立版 ⊆ 工具箱版（零缺失）。
   因此工具箱版 2230 正文行 / 6 张表 / 6499 数据行 与独立版 227 / 5 / 6785 的差异
   **全部**来自上述缺陷修正（第 6 张表 = 尾部 2 行 Custody 小表独立成表）。

## 验收状态

- 合成样例：`cargo test ... pdf_to_excel` 覆盖清洗/折行/金额/前导零/签名/清单/无合并/错误路径。
- 真实样例：`真实回函端到端与独立版对齐`（`#[ignore]`，样例不在时静默跳过）对
  298 页渣打银行回函断言：2230 正文行、6 张表、6499 表格数据行、0 合并单元格、
  10 位账号 723 种（与独立版相同）且 0100684742 原样保留。基准数字经与独立版
  **逐页比对**核实（差异页全部是"独立版多 1 行信头垃圾"，见有意差异 6）。
  该样例含越界矩形、跨页长表、ISIN 折行等全部已知难点形态。
- 未覆盖：纯中文回函、加密 PDF、横排页面等形态无真实样例，未验收。
- 不在发布脚本冷启动门禁清单内（与 Excel Merger/TS/看账/FA/WP/Roll Forward 不同，
  本工具无 fixtures 常驻样例）。
