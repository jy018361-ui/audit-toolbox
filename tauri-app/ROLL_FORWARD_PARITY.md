# Audit Roll Forward Tauri 源码对照验收矩阵

基线源码：`modules/audit-roll-forward/main_gui.py`、`roll_forward_core.py`、`cra_support.py`、`llm_enhancement.py`、`app_settings.py`、`subjects_config.json`。

## 功能矩阵

| 领域 | 旧版能力 | Tauri 迁移状态 | 验收方式 |
|---|---|---|---|
| 项目工作台 | 项目列表、新建、重命名、删除、年度、最近更新 | 已接入新建、编辑、删除、持久化；列表信息在当前项目选择器和公司指标中呈现 | 前端构建；切换工具后返回检查配置 |
| 公司管理 | 添加、重命名、删除、公司独立参数和状态 | 已接入；公司独立保存科目、CRA、路径、参数、生成/失败计数 | 多公司状态测试与人工流程 |
| 基础参数 | 公司、资产负债表日、币种、准则、PM、TE、SAD | 已接入并传入原 `roll_forward_core` | RPC 合约及底稿语义测试 |
| 文件 | 模板目录、上年目录/单文件、输出目录、PMTE | 已接入；PMTE 和全局模板路径持久化 | 路径异常、单文件、目录测试 |
| 科目 | 10 个正式科目、全选/清空、从文件名自动识别 | 已接入；识别规则逐行复刻旧 GUI，含 Uexp/VC&VD 特例 | `test_detect_subjects_*` |
| 处理选项 | wording/分析说明/调整汇总、Summary | 已接入原 Python 内核 | 现有 C 科目语义测试；其余需正式模板金标 |
| CRA 输入 | 粘贴、自动表头、多公司 CRA 列选择、清空 | 已接入解析、表头选项、指定列、清空 | CRA parser 测试及前端流程 |
| CRA 复核 | 写入/确认/跳过状态、搜索与状态筛选、人工编辑 | 已接入搜索、状态筛选、写入开关及字段编辑 | 前端构建与 CRA 样例 |
| Canvas CRA | 链接、接口路径、Token、读取按钮 | 旧版源码本身为“待接口开放”的占位能力；Tauri 不伪造可用接口 | 源码审查 |
| LLM | 增强预检、Review、标黄 wording 修订、连接配置 | 已接入两个处理选项；复用工具箱全局 LLM 配置并从凭据管理器注入，项目中不保存密钥；Dify 不用于旧版只支持的 OpenAI 兼容 Roll Forward 增强 | 运行前 `llmReady` 检查；正式凭据人工验收 |
| 执行 | 单公司、全部公司、逐科目进度、安全暂停、终止 | 已接入常驻引擎与独立 worker；暂停在科目边界生效 | RPC/任务事件测试；多科目样例 |
| 结果 | 每科目成功、失败、消息、输出、Warnings、元数据 | 引擎完整返回；页面结果区显示并记录公司生成/失败计数 | C 科目语义测试；前端结果检查 |
| 输出打开 | 成功后定位输出 | 任务结果输出路径可点击打开 | Tauri 路径白名单验收 |
| 主题/窗口 | PyQt 主题、字号、密度、窗口位置 | 统一归入 Tauri 全局主题与窗口体系，不保留 PyQt 专属实现 | 应用级验收 |
| 引导/反馈 | 新手浮层、反馈问卷 | 属于旧壳层产品功能，统一由 Tauri 应用级体验承接，不进入结转业务内核 | 产品验收 |

## 不可跳过的正式验收

自动测试只能证明接口、控制流和已有 C 科目金标。C、J1、K1、L1、L2、M、N、Q1、Uexp、UexpVCVD 的公式、图片、CRA/PMTE、黄色标记及 wording 必须使用正式脱敏模板逐科目做语义对比；缺少正式样例的科目不得宣称结果完全等价。
