# TS 管理迁移一致性矩阵

## 2026-10-25：自动选表和缓存命中不提前解析全表

- XLSX／XLSM 的显式选表与缓存命中只读取目录；首次自动选表复用公共轻量结构评分（前部窗口＋工作表声明规模），不再逐张物化所有 Sheet 并重读选中表。选表记事升级，与旧按全表有数行计分的结论隔离。
- 规模分使用声明维度，因此格式行／稀疏表的建议可能与旧完整有数行评分不同；用户指定 Sheet 始终优先。正式行数、筛选、透视和输出仍来自完整表。旧格式保持原兼容路径；文本自动标题只读取前部行。
- 回归：`--lib tabular::`，包含正表／核对副本、人工指定／无效表名及缓存破损重建；前端 `src/TsManagerParityPage.test.ts`。统一约定见 `TABLE_READ_POLICY.md`。

## 2026-10-25：预览区补齐表头层数

前端文件名与 Sheet／标题行／表头层数统一到预览标题栏；读取、筛选值查询、筛选和导出均传递当前 `headerDepth`，历史未保存该字段的草稿默认单层。改变层数清除旧预览与筛选值缓存，重新读表后继续原工时透视规则；Rust 本次不改 TS 处理逻辑。回归：`npx vitest run src/TsManagerParityPage.test.ts`、`npm run build`。

## 2026-10-21：公共表头结构候选修复

自动表头识别继承公共短字段／段落筛选、后续正文及联合双层边界判据，避免说明段落仅凭业务词胜出；明确参数页要求选择数据表或手动指定表头。批量账表扫描保留同本有效 Sheet；普通与大文件入口使用一致结构规则，旧识别／结果缓存失效。各工具自身字段词表、人工指定及业务计算规则保持。接入范围、限制及回归命令见 `HEADER_DETECTION.md` 同日条目。

## 2026-10-21：已确认表头与公共识别保持同名

共享 Polars／文本读取的单层列名改为调用公共 `fx::merge_headers`：空标题统一为按位置生成的“列N”，换行统一为空格，重名保留独立编号。修复自动识别显示“列N”、确认重读却变为“Column_N”的差异；单层不再向右借用左侧字段，双层分组仍延续。稳定表缓存引用公共表头规则版本，旧名称不复用。TS 仍由用户指定表头行，看账／凭证正负数处理规则保持。回归：`cargo test --manifest-path src-tauri/Cargo.toml --lib tabular::`、`--lib disk_table::`、`--lib fx::`。

## 2026-08-05 迁移差异审计与修复

本轮对九个工具做了逐项"旧版 vs 新版"审计，结论按"功能没了 / 结果可能不一样 / 少了提醒 / 本来就该丢掉 / 新版更好 / 光看代码说不准"六类归档。
以下只记录**本工具**已落地的修复；**尚未用真实脱敏底稿验证**，所有"已修复"仅代表通过了合成回归。

### 已修复

- **首次读取不落缓存**：`ts.inspect` 原走不落缓存的读取路径，同一文件在一次会话里被完整解析三次（加载、取筛选值、导出）。现首次读取即写稳定 Parquet 缓存。
- **多 Sheet 静默取第一个**：新增醒目提示，说明当前用的是哪张表、共有几张。
- **导出结果不显示**：引擎返回的 by经理/by项目行数、明细行数、耗时现已在界面呈现。
- **候选值截断无提示**：显示"已加载 N / 共 M"。
- **读取阶段无进度、无法取消**：`ts.inspect` 改走任务通道。
- **耗时预期文案**：旧版界面明写"导出需要 5 分钟""勾选会额外等待约 1 分钟"，迁移时删光，现已补回。

### 结果差异（新版更正确，但与旧版不同）

- **旧版会把透视表里空白的行标签填成上一行的值**（李四职级为空即显示成张三的职级），且旧版行序随机，填入的值本身也随机——这是凭空造数。新版留空。**若历史上有基于旧版导出做过按职级/类型维度的分析，结论需要复核。**
- **旧版筛选值填错会静默丢弃整条筛选条件**并导出全量；新版精确匹配，匹配不到即 0 行。
- **旧版缓存文件名用了每次启动都会变的哈希**，跨会话从不命中；新版用内容指纹，真正复用。

### 与看账共用数据层的连带影响

`tabular.rs` 由 TS 与看账共用，以下三处为看账定的口径同时改变了 TS 的行为，任何一处调整都需同时回归 TS：金额解析（去千分位）、整行全空即丢弃、单元格转文本规则（决定项目编码形态与月份列表头）。
