# UI/UX 布局验收

## 覆盖模型

验收按界面状态分成三条独立门禁，避免只检查空页面：

- 静态层级：工作台、历史、设置和 18 个工具，共 21 个入口；覆盖共享断点两侧、1000px 最小窗口，以及 125%/150% 缩放后的等效 CSS 视口。
- 真实工作流：18 个工具使用预览演示数据实际点击文件选择、识别、映射、下一步和执行按钮；每个达到的业务状态分别检查页顶、滚动中段和页底，覆盖 1600/1180/1000px。
- 任务变化：18 个工具分别检查读取中、排队、运行、内存暂停、取消、失败、完成、部分完成、恢复输入、历史继续，共 540 组。
- 浮层：确认框、同步等待、多任务弹窗、任务最小化条、完整引导、步骤提示、完成提示、行话提示、模糊匹配确认框、窄屏导航抽屉及设置更新面板。

真实浏览器几何检查包括：页面与容器横向溢出、裁切、流式兄弟重叠、控件越界、长路径/长错误换行、浮层视口边界、可滚动区域、交互目标尺寸、模态焦点归属，以及终态仍出现取消按钮等状态矛盾。

## 本轮发现并修复

- 设置页连续字段没有纵向布局契约，选择框焦点环会压住下一行；统一字段为 grid，并为卡片直接子项建立固定间距。
- `body` 的 980px 硬最小宽度会在高缩放下制造整页横向滚动；移除硬下限，由 1179px 以下的导航抽屉接管。
- 通用结果文件按钮继承 `white-space: nowrap`，任务完成后长路径会把所有工具撑到 1050px；结果列表改为可安全断行。
- 任务消息、错误、警告和输出路径统一增加 `min-width: 0`、长词换行、列表限高与内部滚动；终态不再提供取消操作。
- 多任务、同步等待和确认弹窗增加动态视口限高、内部滚动及稳定操作区；最小化任务条限制宽度并归还焦点。
- 新手引导在目标定位完成后重新把焦点交给主操作按钮；抽屉打开时背景设为 inert、锁定滚动，关闭后归还焦点。
- 行话提示改用 body portal + fixed 定位，避免被卡片裁切；问号触发区不再用负 margin 撑破字段。

## 执行方式

开发夹具仅在 Vite 开发环境可用，不进入桌面业务路径：

1. `npx vite --host 127.0.0.1 --port 1420`
2. `npm run audit:layout:tasks`
3. `npm run audit:layout:overlays`
4. `npm run build`
5. `npx vite preview --host 127.0.0.1 --port 1422`
6. `npm run audit:layout:static`
7. `npm run audit:layout:workflows`
8. `npx vitest run --exclude=.claude/**`

每个脚本都会把 JSON 报告和失败截图写入系统临时目录；发现几何或语义问题时返回非零退出码。

## 验收边界

- 125%/150% 项验证的是等效 CSS 可用宽度，不冒充 Windows 显示设置下的原生 WebView2 测试。
- 原生标题栏、Windows 系统缩放切换和读屏器仍需在打包后的 Tauri 应用中做发布前实机验收。
- 浏览器夹具验证 UI 状态容错，不替代 Rust worker、Excel COM 或真实客户文件的业务验收。
- 真实工作流门禁验证已建立演示数据的页面状态；客户文件才有的极端列数、超长单元格和系统字体差异仍属于发布前实机抽样范围。
