# UI 修改记录

## 2026-09-04 · 看账导出容错与批次操作

### 目标

- 让纵向合并产生的大 CSV 可直接用于看账导出，并清除已迁出功能留下的界面误导。
- 提供一次删除所有目标批次的操作，避免逐个删除自动生成的批次。

### 设计决策

- 大 CSV 磁盘流程识别并跳过文件中间的重复表头，复用已有行缓存；科目索引单独升级重建。其他无法解析的金额值继续严格报错，并在界面直接显示列名、源文件行号和值。
- 动态内存保护在空闲内存偏低时改用约 10% 物理内存的硬安全底线，并把 worker 限额收缩到剩余安全余量的一半；16 GiB 主机剩余约 3 GiB 时可进入慢速磁盘流程，不再因略低于原 20% 保留线而立即拒绝。
- “低内存磁盘模式”更名为“磁盘分批模式”，并说明内存上限、缓存与批量仍会动态调整。首次汇总科目时显示已扫描行数和百分比，任务可取消；第一步生成的科目索引进入第二步直接复用。最小化任务改为最高层级的高对比常驻入口，明确提示点击展开。
- 运行中的内存熔断改为随主机内存缩放的紧急阈值，并要求压力持续 5 秒；避免 Windows 文件缓存瞬时波动造成导出黑框一闪后立即失败。
- 科目筛选中的“智能对冲”和页头“JE 匹配”文案删除。该能力已迁到“正负数凭证标记”工具，看账只按目标科目扩展完整凭证。
- “删除当前批次”旁新增“一键删除全部批次”，点击后恢复一个可继续编辑的空白“批次1”，同时清除预设摘要与批次选择状态；剔除/例外清单继续保留。

### 验证方式

- 大 CSV 重复表头 Rust 回归、看账批次前端回归、`npm run build`；并用真实 6.41 GB 文件的现有缓存复核金额错误不再由 12 行重复表头触发。

### 目标

- 部门内部使用：默认开启、无弹窗；设置页可关、可改服务器地址；发送失败静默缓存补发，绝不影响正常使用。

- 事件字段结构性收窄：安装编号＋事件名＋工具＋版本＋电脑名/系统用户＋成功与耗时，不存在携带文件路径、账表内容、客户数据的通道。

- 前端只允许上报 `tool_open`（`telemetry_track` 命令白名单），其余事件由 Rust 自己记录：启动在 setup、退出在 `RunEvent::Exit`（记会话时长，2 秒超时内尽力补发）、任务终态在 `excel_merger` 的 emit 单点挂接（按 jobId 取走启动时刻，天然去重，取消/失败都算未成功）。

## 2026-09-03 · TBJE 完整性：二次添加文件不再丢失已确认的配对

### 目标

- 用户反馈：回到第 1 步二次添加文件、再返回配对页时，之前（含手工）配好的信息全部丢失。

### 根因与设计决策

- **根因**：`intake()` 每次添加文件都把「现有文件＋新文件」整体丢给自动配对重建全部组——用户在配对页手工换过的 JE、手工选的「不配对序时账」被自动规则原样冲掉；重复选入同一份文件还会重置已选的工作表和字段映射。
- **新的合并策略**：已配好对的组原样保留；只有「没配上 JE 的 TB」和「没被认领的 JE」与新文件一起重新自动配对——分两批拖入仍能跨批次配上，但用户看过的结果不再被翻动。
- **手工「不配对」也算确认**：明确选过「不配对序时账」的 TB 组在二次添加后保持不配，不会被新 JE 强行塞回（内部用 clearedTbs 记录，移除组时同步清理）。
- **LLM 联合复核结论跟组走**：组还在就算复核过，只有组解散才清掉；复核状态行的过时计数复位。
- **重复选入同一文件跳过重新识别**：工作表选择、手工改过的字段映射得以保留，只当「确认要这份」。

### 已修改

- `src/tbjePairing.ts`：抽出 `compareGroups` 统一排序供配对与合并复用。
- `src/TbjeCheckPage.tsx`：`intake()` 改为增量合并；`selectJe`/`removeGroup`/`removeAllGroups` 维护手工清空记录。

### 验证

- 新增回归测试两项：二次添加保留手工「不配对」且新文件照常自动配对；重复选入同一文件不重新识别、配对不变。
- `npx vitest run src/TbjeCheckPage.test.tsx src/tbjePairing.test.ts`（18 项全绿）、`npm run build` 通过。

## 2026-09-03 · TBJE 完整性：确认配对表在窄窗口溢出修复

### 目标

- 用户截图反馈「TBJE完整性 UI 都溢出了」：确认配对这一步的表格在 125%/150% 显示缩放的笔记本窗口上，最右侧「映射与操作」按钮列被整列推出屏幕、只能靠不显眼的横向滚动条补救；长组名还会直接压在 TB 文件列上。

### 根因与设计决策

- **长组名压列（重叠 bug）**：配对组名取自文件名（有编号时是"04"这类短号，没编号时是整个文件名主干，如"汇兑损益审计测算_20260821_085727"，实测 262px）。原第一列固定 100px 且组名禁换行，文字直接溢出盖住 TB 文件列约 150px。改为：第一列固定 96px，组名省略号截断、悬停显示全名（title）。

## 2026-09-02 · 存款利息账面利息收入的符号语义 v2

### 目标

- 账面利息收入基准按「表级符号口径＋红字＋科目登记方向」取数：费用性质的科目计入负数冲减基准，不再冒充一笔正的收入。

### 用户反馈

- PL 科目有借贷方向：利息收入一般在贷方；如果金额实际在借方（费用性质），应计负数。
- 公共引擎已有符号判定能力（勾稽等式投票、红字两侧拆分），应接入而不是各写一份。

### 设计决策

- 表级口径用 `detect_tb_sign_convention`（勾稽等式投票；用户实测用友表判 Unsigned 152:0），`calculate()` 里本就为余额算好，直接传入发生额取数。Unsigned 表净额按 `贷－借`（红字天然归对面一侧），Signed 表按 `－贷－借`——修掉旧逻辑在 Signed 表已结转行算出 2 倍金额的隐患。
- 已结转形态（借贷同额、净额为 0）：按「科目登记方向 × 红字」定符号。方向由 `registered_direction` 从科目名称＋TB 祖先科目推断（费用类关键词优先于收入类——`财务费用-利息收入` 挂在费用科目下，登记方向是借）；规则矩阵：
  - 费用方向＋红字对＝冲减费用＝**收入 +X**（用友记法 `财务费用-利息`，用户文件实测 923,800.50）；
  - 费用方向＋正常对＝**费用 −X**（冲减基准）；
  - 收入方向＋正常对＝**收入 +X**；收入方向＋红字对＝**−X**；
  - 方向未知＝按全额 +X 计入并提示复核（尊重科目分类里的人工指定）。
- 汇总层 `bookedInterestIncome` 保留符号，新增 `bookedNote`（净支出提示）；逐行 `bookedInterestRows` 带 `note` 口径说明，导出底稿「账面利息收入科目明细」加「口径」列。

### 已修改

## 2026-09-02 · FA TB＋JE 调整分录原封进底稿与凭证键显示 v1

### 目标

- 固定资产 TB＋JE 变动表中，原值／折旧的类别间调整分录不再被当作「无法归属到原值类别」的审计告警，原封不动保留在固定资产汇总变动表和新增／处置清单里。
- 底稿各表的「凭证键」列只显示凭证识别字段（如「记-0067」），不再拼主体与日期。

### 用户反馈

- 用汇兑损益测试资料（序时账-1 ＋ 科目余额表）测试时出现 3 条「有累计折旧变动 … 无法归属到原值类别」；用户定性：原值与折旧的调整是正常账务处理，不是审计发现，要逐笔保留在底稿里。

### 设计决策

- 折旧变动不再按「类别是否在 TB 原值侧存在」分流：贷方进「本年计提/其他增加」、借方进「折旧其他减少」；「未归属折旧」列与告警整体删除。16020002 机械设备（TB 原值侧无同名类别）在汇总表自成一行：期初 425082.62、计提 82467.38、重分类 −507550、期末 0、勾稽差异 0。
- 折旧类别间调整凭证（无原值变动、折旧有增有减，如记-0059「折旧科目调整」）与原值重分类同一口径：金额进「重分类净额」列，两侧以「重分类转入／转出」进新增／处置清单（原值列 0、折旧列金额）；计提与调整同凭证时按类别聚合值原封落列，不拆分。
- 原值重分类凭证此前只进汇总表，本轮起转入／转出侧同样进清单（kind＝重分类转入／转出、方式＝原值/折旧类别间调整）。
- 凭证键列只显示凭证识别字段原文；清单 SUMIFS 改按「主体＋凭证键＋日期」三维过滤，避免同主体跨日同号凭证金额被合并；顺带修掉内部连接符 `\u{1f}` 落 xlsx 变 `_x001F_` 的问题。

### 已修改

- `src-tauri/src/fa_tbje.rs`：分类核心、五张底稿表输出与公式；新增合成回归与真实样例 ignored 回归（`FA_TBJE_FX_DIR`）。前端无改动（结果区告警数随数据自然归零）。
