# FY27 WP 服务单 Rust 迁移说明

`src-tauri/src/wp.rs` 是原 `modules/wp-service-generator` 的纯 Rust 业务内核。生产接入后不再启动 Python、PowerShell 或 Excel COM。

## 已复刻范围

- 在所选目录第一层按关键词唯一识别 WP 服务单与 Section List，读取“业务”Sheet 并校验七个必填表头。
- 按旧规则拆分 `AUD2026`、`IPO`、`IPO archive`、`AUD2025`，保留不纳入记录及 IPO 年份说明。
- 只为 `AUD2026` 与活动 `IPO` 的唯一 WP 服务单生成方案。
- 读取可变列序的 Section List，规范化服务单号和 Section 名称，合并重复 Section 的 Entity、底稿数量和预算调整。
- 无损复制脱敏模板的 32 行 Section、版式和基础样式，回填项目、Booking Period、Section 数量。
- 生成标准参考工时、Section Outlook Hours、项目 Outlook Hours 及 SER 的全部旧版公式。
- 支持同目录 `SER配置.xlsx`，沿用四行、正数及合计 100% 校验。
- 源表服务单/相关订单回链、服务方案返回源表、服务方案索引和核对结果。
- 生成后回读检查五张基础表、服务方案数、32 个 Section、关键公式和索引行数。
- 先写临时文件再替换结果，避免失败留下半成品。

## 主路由接入点

1. 在 `src-tauri/src/lib.rs` 声明 `mod wp;`。
2. `wp.inspect` 可直接检查三个输入路径；耗时任务 `wp.generate` 调用：

```rust
let params: wp::WpGenerateParams = serde_json::from_value(params)?;
let result = wp::generate(&params)?;
```

3. `WpGenerateResult` 已实现 `Serialize`，可以直接作为任务结果发送给前端。
4. 建议输出默认值继续使用输入文件所在目录的 `FY27+WP服务单汇总.xlsx`。

## 验收标准

- 合成样例：四类各 1 行；活动 AUD/IPO 各生成 1 张方案，archive/历史表不生成。
- Section：两个服务单匹配，重复项合并；Outlook 比较数量和一致数量与旧版相同。
- 结果语义：基础 Sheet、服务方案、索引、公式、回链及 SER 配置全部可回读。

最终复测发现模板的部分 Section 使用富文本共享字符串；`umya-spreadsheet` 能保留样式，但读取这些单元格时只暴露部分文本 run，导致完整 Section 名无法与 Section List 对齐。现改为由 Calamine 读取完整模板 Section 与参考工时，复制模板时再把完整 B5:B36 写回，同时保留 umya 的样式和工作簿结构。`cargo test wp::tests:: -- --nocapture` 最终为 5 项全部通过，覆盖规范化、四类拆分、`wp.validate` 契约、预取消及完整合成工作簿；合成验收数字为服务方案 2、四类拆分各 1、匹配服务单 2、匹配 Section 3、Outlook 比较 2 且一致 2。

以上自动验收不替代正式客户模板金标。生产发布前仍应核验 Sheet、值、公式、格式、合并区域、超链接、条件格式、打印设置和关键列宽。

## 2026-08-05 迁移差异审计与修复

本轮对九个工具做了逐项"旧版 vs 新版"审计，结论按"功能没了 / 结果可能不一样 / 少了提醒 / 本来就该丢掉 / 新版更好 / 光看代码说不准"六类归档。
以下只记录**本工具**已落地的修复；**尚未用真实脱敏底稿验证**，所有"已修复"仅代表通过了合成回归。

### 已修复

- **打印区域写成非法地址**：四张源表的打印区域拼接多了一个 `$`（`$A$1:$W$$5`），Excel 打开时可能提示"发现不可读取的内容"并在修复后丢弃该设置。已修正。（顺带发现：原有测试断言"工作簿级别存在打印区域定义名"之所以能通过，恰恰是因为地址非法——地址合法时会被正确挂到所属工作表上。断言已改为语义正确的版本。）
- **Entity 数量列随机选取**：Section List 存在多个 `Entity数量…` 变体时按哈希表迭代顺序取列，**同一份文件连续两次运行可能取到不同列**，工时与 Outlook 核对结论随之改变。改为按列序取第一个匹配列。
- **日期解析过严且默认月份**：`2026年4月`、`2026.04` 等写法解析失败会导致整行 IPO 记录被剔除；只写年份时月份默认为 1，会命中"2026 年 1–3 月"而被误判为 IPO archive、不生成服务方案。改为取开头四位数字作年份、月份缺失即视为未知（不参与 archive 判定）。
- **界面完全不显示结果**：本工具是九个里唯一没有专用页面的，走通用表单。通用页原本只把 `{jobId}` 当结果渲染，导致引擎算出的 25 个字段一个都看不到。现通用页订阅任务事件并渲染真实结果：服务方案张数、四类行数、匹配服务单数、有数据 Section 数、Outlook 可核对/一致数、**未匹配 Section List 的服务单清单**、**Outlook 逐条差异明细**，以及"检查输入"的通过与缺失文件。
- **报错显示为 `[object Object]`**：Rust 返回的是普通对象而非 `Error`，其余八个工具各自写了中文提示提取，唯独通用页没有。已补。

### 仍未清零

- 生成后的深度自检大幅缩水：旧版会逐格复核 Section 回填值、SER 四档占比与费率、索引页与源表 Outlook Hours 一致性，并解压检查包内每个部件；新版只检查表存在、张数、32 项 Section 与若干公式文本。**回填值出错时旧版拦下，新版照常出文件。**
  （2026-08-10 补充：拿真实样例跑旧版 `validate_workbook` + `validate_formula_logic` 核对新版产物，两项均通过，
  即回填值本身是对的；但**新版自身仍不做这层检查**，这条依旧没清零。）

- 服务方案页的四个 Booking Period 日期以序列号写入且未设日期格式，可能显示为五位数字。
  （仅当来源导出把日期存成真日期时才触发；本次真实样例里这四列是文本，两版写出的都是同样的文本。）
- 索引页的"缩放到一页宽"开关所用写库不支持，参数写了但开关没开。→ **2026-08-10 已修**（写盘后补 `pageSetUpPr`）。
- 未设"打开时全部重算"，公式可能开档显示 0 直到手动重算。→ **2026-08-10 已修**（写盘后补 `calcPr`）。
- ~~未显式指定活动工作表，打开时停留位置不确定（旧版强制停在索引页）。~~
  2026-08-10 实测两版的活动工作表都是"服务方案索引"，这条当初记错了。
  真正存在的问题是 85 张服务方案的标签页处于成组选中状态，已一并修复。

## 2026-08-10 拿真实样例与旧版 Python 逐格比对

首次用真实（脱敏）导出跑通"旧版 Python vs Rust"同输入对比：166 行业务表 + 2622 行 Section List，
两版都产出 90 张表 / 85 张服务方案，四类拆分 55/30/6/54，Section 匹配 49 个服务单、1764 条、405 条有数据，
Outlook 可核对 48 个、一致 7 个——**统计口径本来就一致**。逐格比对暴露的是排版与内容侧的问题：

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| 85 张服务方案全部是隐藏表 | 模板在拆分簿里是隐藏表，克隆时继承了状态。**Excel 打开只看得到 5 张基础表，交付物一张都看不见** | 克隆后复位为 visible |
| 模板中文标签成片丢失/截断 | umya 对富文本共享字符串只暴露第一段 run：`WP服务单编号`→`WP`、`Entity数量`→`Entity`、`底稿数量`/`标准参考工时`/`预算调整`/`序号`/`相关订单`→空，**整块"二、基本时间表"（阶段、预审下场时间…报告日 共 17 个标签）全空** | 用 Calamine 读全表文本，版式定型后整表写回；拆分簿里的隐藏模板同样处理 |
| 来源表多出模板遗留列 | 基础表是从模板表克隆的，模板有 22 列（U=Client Code、V=相关项目），导出只有 20 列，U/V 连值带样式留了下来，还把 `Client Code` 的列宽抢到了 U 列 | 改为和旧版一样新建空表 |
| 打印区域/顶端标题行失效 | 定义名没写 `localSheetId`，90 张表写出 90 组同名工作簿级定义名，Excel 判重复后丢弃 | 写盘前按表序号补 `localSheetId` |
| 文本数字被转成数值 | umya `set_value` 会嗅探字符串：`Engagement Code`、`Client Code`、`底稿任务数量`、序号列全部由文本变数值 | 改用 `set_value_string`，空值走 `set_blank` |
| 服务方案 E1:H1 被刷成深蓝表头 | 旧版这四格是无边框白底正文 | 按旧版重刷 |
| 两条分节标题（39/55 行）四周加了网格线 | 旧版只有一条深蓝中粗下边框 | 单独的标题样式 |
| 时间表 C41:C54 未居中；序号列、索引首两行、索引 A/B/J/K 列多了自动换行；索引标题条多了网格线 | 排版与旧版不符 | 逐项对齐 |
| 85 张服务方案的标签页全部处于"被选中"状态 | 同样是从模板克隆带来的。Excel 打开即成组选中，此时在任一格输入会同时写进所有 85 张表 | 统一复位 `tabSelected` |
| 条件格式的差异格式带了字体名/字号 | 命中"已完成/项目承接"时会把该格字体改掉 | dxf 只留加粗与颜色 |
| B56（Total Outlook Hours）缺 `#,##0.00` | 显示口径不一致 | 补 |
| 拆分簿的四张裸表被提前排版、页边距为 0 | 旧版拆分簿是无格式的中间产物 | 拆分路径不排版，页边距用 Excel 默认值 |

比对方式：同一份输入分别跑旧版 `generate_wp_project_workbook.py` 和 Rust，然后逐表逐格比
**值 / 公式 / 数字格式 / 字体（名·字号·加粗·斜体·颜色·下划线）/ 填充 / 对齐（水平·垂直·换行）/ 边框四边 /
行高 / 列宽 / 合并区域 / 冻结窗格 / 自动筛选 / 条件格式 / 打印方向·纸张·缩放·页边距·打印区域·顶端标题行 /
页脚 / 网格线 / 缩放比例 / 标签页颜色 / 工作表可见性 / 工作簿计算属性 / 活动工作表 / 定义名**；

修复后 **汇总工作簿（90 张表）在以上全部维度与旧版逐格一致**，并且直接拿旧版自己的验收函数
（`validate_workbook` + `validate_formula_logic`，后者会逐格复核 Section 回填值、SER 四档、索引 WP FIC 与

剩三处已知差异，均无视觉影响、不再追平：

运行：`cargo test --manifest-path src-tauri/Cargo.toml wp::`；
对真实样例复跑用 `WP_REAL_FOLDER=<目录> cargo test --lib wp::tests::real_sample_generate -- --ignored`。

**仍未做**：没有在真实 Excel 里打开确认无"发现不可读取的内容"提示；上述结论全部来自文件结构比对。
