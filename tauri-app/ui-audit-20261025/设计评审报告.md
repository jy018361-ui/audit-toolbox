# 界面设计评审报告（2026-10-25 · 设计总监视角）

> 评审对象：修复后全部 19 个工具的全步骤、应用壳、弹窗与任务状态层，共 151 张截图（`ui-audit-20261025/shots/`）。
> 评审标准：五轴各 1-10 分——A 间距节奏 / B 布局平衡 / C 视觉层级（3 秒测试）/ D 信息冗余与密度 / E 一致性细节。
> 与此前「缺陷验收」的区别：本轮只评设计品质——好看不好用之外，重点评「笃定不笃定」。

## 一、总评

**设计语言已经立住，观感差距不在单屏质量，在跨屏纪律。**

独立评审的四个组在互不通气的情况下给出了高度收敛的诊断：单屏功夫普遍在 7 分档（表单密度、对齐、状态芯片的功夫是真实存在的），失分几乎全部来自**跨屏不一致**——同一信息说 2~4 遍、黄色一种颜色承担五种语义、表格行高六种并存、主按钮三种范式、结果页三种形态。这就是「规整」与「笃定」之间的距离。

- **全组均分约 6.9 / 10**。分布：8 分档 9 屏（多为空态与简单表单屏——「少即是多」的直接证据），7 分档约 55 屏，6 分档约 22 屏，5 分档 4 屏（全是「长文本撑爆 + 语义色错位」的屏）。
- **最低分共性**：overlay-confirm（5.0）、新手引导（4.7）、函证 step4（5.5）、存款结果页（6.0）、看账批次屏（6.0）——全部是「内容长度不受控 + 提示无分级」的叠加，无一例外。
- **最高分共性**：工作台（7.6）、折旧测算（8.0）、函证空态（8.0）、TS 首屏（8.0）——空态干净、单卡单义。

**三秒测试**是本轮最有价值的发现：大部分屏的主角落点正确（上传屏→拖放区、结果屏→绿色结论、待办屏→黄色组卡）；失败的三类屏是——结果页被黄色警示墙劫持（存款 step3）、批次屏看不出「在编辑哪个批次」（看账 step3）、确认框读不出「确认的是什么」（overlay-confirm）。

## 三、五大系统病（四组评审独立收敛于同一诊断）

1. **提示无分级**：黄色一色承担错误/待办/口径解释/门禁/加载失败五种语义；存款结果页四连黄 230px；函证成功条误用琥珀；partial 明细误用红。缺 `error / warning / info / success` 四级 + 「1 条行动条 + ▸ 其他 N 条」聚合机制（sync 弹窗的 ×N 聚合就是现成范式）。
2. **同一信息说 2~4 遍**：文件状态 ×3（chip+路径条+识别面板）、完成数字 ×2（横幅+算式）、「待补利率」×4、Sheet 名 ×3、「留空表示不修改」×3、卡题与步骤条双重编号——缺「一个事实一个位置」的密度纪律。
3. **状态不可见**：批次 chips 无选中态、透视字段行高亮 1.3:1、禁用按钮两套色且时而「未就绪即深色可用」、开始匹配就绪态与禁用同色——缺一套强制的「选中=深绿底白字、禁用=灰青+原因」规范。
4. **长文本零防御**：confirm 正文、引导气泡、术语 tooltip、成功 toast、任务消息全部整段铺开，无一执行「1~2 行省略 + 展开」；这是全部 5 分屏的共同根因。
5. **缺布局 token**：表格行高实测 32/40/47/64/68/76/80px 七种；主 CTA 时而画布右下、时而卡内左下、时而标题行；「选择/浏览/打开」动词漂移；结果页三种形态（独立卡/内联/胶囊）。

## 四、设计规范提案（把「规整」变「笃定」的六个约定）

1. **语义色四级**：`success` 绿＝完成/已识别；`warning` 琥珀＝待办/例外（每屏最多 1 条可行动黄条）；`info` 灰蓝＝口径解释与「系统预设」类非警告信息；`danger` 红＝仅破坏性动作。同屏 ≥3 条提示时聚合为「1 条行动条 + ▸ 其他 N 条」。
2. **长文本规范**：名称/路径/消息一律 1~2 行省略 + 统一「展开」控件；确认框标题必须是动宾句带计数（「删除 N 条失败记录？」）；术语 tooltip ≤3 行 +「查看完整说明」。
3. **布局 token**：表格行高 44px（表头 40px）、表内控件行高 40px；卡片内外边距 24/16；主 CTA 统一画布右下（宽 ≥120px）；一屏一个深色主按钮，成功后主按钮转次级「重新生成」、深色让给「打开结果」。
4. **状态样式**：选中＝深绿底白字（批次 chips、透视字段行、列表选中行统一）；禁用＝灰青 + 伴生原因（「请先选择文件」）；「已用/已确认」绿 chip 为全站唯一确认语言。
5. **结果页契约**：交付物第一（成功横幅=图标+一句话+「打开输出」主按钮，紧跟步骤条之下）；输入回显折叠为单行摘要；「结论（绿）→ 例外（黄）→ 明细」的阅读顺序在所有结果页成立。
6. **工具页契约**：凡出现步骤条，则步骤条标签 = 卡片标题 = 按钮动词三处同词；卡片不另编号；与滚动无联动的装饰性步骤条移除；同一参数全站同一控件形态（标题行/表头层数二选一）。

**只允许改三件事时的答案**（四组评审的答案完全一致）：① 提示分级与聚合；② 状态/禁用/选中的样式规范；③ 结果页「交付物第一 + 数字只说一遍」。做完这三件，整体观感从「规整」上一个台阶到「笃定」。

## 六、值得保留的资产（评审一致点名的好设计）

- 「A 对比 B = 差异」算式结果卡（全组最好的结果表达，数字层级 12px 标/20px 值）；
- sync 弹窗的「×N 聚合」降噪（应推广为提示聚合的范式）；
- 列头内嵌映射下拉 + 「已用/—」绿灰二元状态（学一次用两次）；
- 汇兑上传屏的硬约束前置一行（缺任一列无法测算——把失败消灭在上传前）；
- 函证空态「检查后这里显示什么」的预期管理；TS 首屏同款；
- 借款测算门的「暂估值不会被视作已确认依据」审计语义写进 UI；
- 存款导出成功条的往返契约文案（黄色单元格可改、导入即重算）；
- 1000px 窄屏的图标栏降级（三处降级全部干净不破相）。
